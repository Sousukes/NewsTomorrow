## 两条维护约定

1. **新写的内容进 `docs/`，不要往已拆出的文件里塞。** 单文件超过 ~20KB 就该拆——
   这是本次拆分的直接原因（落地记录曾到 217KB，已经无法检索）。
2. **索引里的链接必须指向真实文件**：有测试遍历所有索引并校验链接可达
   （`server-api/tests/test_docs_index.py`）。拆分文档最怕的就是拆完链接全断，
   而那种断裂没有任何症状。

## 为什么会有「主文档只留索引」这回事

原始形态是三个巨型文件（后端 README 137KB、前端 README 68KB、落地记录 217KB），
加一份 137KB 的速查表。问题不是"不好看"，而是**它们已经无法被检索**：
在 2000 多行里找一个错误码要靠 Ctrl+F 全文件翻，编辑器跳转全靠滚动。
拆分后单篇最大的约 40KB，其余都在 10KB 以内。
