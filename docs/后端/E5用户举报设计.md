# E5 用户举报 · 设计方案（定案）

> 状态：**设计已定，待实现**。决策点由用户 2026-10-18 确认，实现前可再调。
> 来源：backlog E5「内容治理只有机器审核 + 运营后台，用户侧无反馈通道」。

## 一、已确认的 4 个决策

| 决策点 | 结论 |
| --- | --- |
| 举报对象 | **评论 + 资讯**（统一举报体系，对象可扩展） |
| 举报理由 | **预设分类**（色情低俗 / 政治敏感 / 广告营销 / 侵权 / 谣言不实 / 其他） |
| 处置策略 | **达阈值自动软隐藏/下架 + 人工复核**（防刷去重后的举报数，阈值默认 3，可配置） |
| 登录要求 | **必须登录**（复用 `user_id` + 限流 + 幂等，防刷最稳） |

## 二、沿用现有体系（不新造）

- **软隐藏/软下架**：评论用现有 `hidden`/`hidden_reason`（P1-22）；资讯用现有 `hidden`/`hidden_reason`（P1-20）。公开查询已统一过滤 `hidden`，自动处置后**前端无感知地消失**。
- **人工复核**：复用现有管理后台结构 + `AdminAuditLog` 审计（新增 `admin/reports.py`）。
- **防刷**：复用登录态 + 现有限流器。
- **不做**（第一版）：举报人结果通知（`messages` 体系后续可加）、自由文本理由、匿名举报。

## 三、数据模型（迁移 0031）

`reports` 表：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Integer PK | |
| `reporter_id` | Integer FK users | 举报人 |
| `target_type` | String | `comment` \| `news` |
| `target_id` | String | 评论 id 或资讯 id |
| `reason` | String | 预设枚举之一 |
| `status` | String | `pending`（待复核）\| `resolved`（已处置）\| `dismissed`（驳回） |
| `created_at` | String | 绝对时间 |
| `resolved_at` | String 可空 | |
| `resolved_by` | String 可空 | 管理员手机号 |
| `resolution` | String 可空 | `hidden` \| `kept`（人工结论） |

**幂等约束**：`UNIQUE(reporter_id, target_type, target_id)`——同一用户对同一目标重复举报**更新 reason，不新增行**（防刷）。

**不建外键到评论/资讯**：`target_id` 是异构主键（评论/资讯两类 id），无法用单一 FK；且目标被删后举报记录仍需留存（审计溯源）。目标删除时举报行保留，复核页显示「目标已删除」。

## 四、自动处置阈值语义

- **计数口径**：去重后（不同用户）的 `pending` 举报数 ≥ `REPORT_AUTO_HIDE_THRESHOLD`（默认 3）。
- 达到阈值时：对评论 `hidden=True, hidden_reason='用户举报'`；对资讯同理。**只对当前 status=pending 的举报触发**，已 dismiss 的不计。
- 阈值是**防刷的关键**：单用户去重后最多贡献 1 次，想刷下架一条内容需要 3 个真实账号——成本显著上升。
- 自动处置**不直接删除**，进复核队列，运营可「恢复」或「确认」。

## 五、接口

**用户侧**（需登录）：
- `POST /api/reports`：`{ targetType, targetId, reason }` → 幂等 upsert；返回 `{ status, autoHidden }`（autoHidden 表示本次是否触发了自动隐藏）。
- 目标不存在 → 404；reason 非法 → 422。

**管理端**（复用 `require_admin`，D2 后挂在聚合 router 自动受保护）：
- `GET /api/admin/reports?status=&targetType=`：复核队列。
- `POST /api/admin/reports/{id}/resolve`：`{ resolution: 'hidden'|'kept' }`，落 `resolved_by`/`resolved_at`/审计。

**错误码**：实现前先查占用（记忆 #11），目标不存在/参数非法按现有惯例分配。

## 六、前端交互

- 评论详情页 + 资讯详情页各加「举报」入口（评论在长按/更多菜单，资讯在页面操作区）。
- 点举报 → 弹窗（预设分类单选）→ 提交 → 提示「已提交，感谢反馈」。
- 举报后**不显示处置结果**（第一版不做通知，避免被举报人反向锁定）。
- 评论被自动隐藏后，举报人本人仍可见（软隐藏语义：本人可见、他人不可见，P1-22 已有）。
