# 债务 backlog（F5 · P1-32 建立）

> **本文件是开放债务的唯一跟踪入口**。审查报告
> （`architecture-review-2026-10-17.md`）是 2026-10-17 的历史快照，保留完整
> 分析与证据，**不再增量维护开放项**——两处各记一半，必然漂移。
>
> **背景**：F5 的立项证据是「10-11 的 11 项 High 中 7 项仍存活」——审查
> 产出无法闭环，债务只增不减。根因不是没有清单，而是清单没有**偿还规则**：
> 没有规则的 backlog 等于没有 backlog。

## 偿还规则（本文件存在的理由）

1. **每个功能批次固定偿还 1~2 项**，取本表最上方的未完成项。顺序即建议
   优先级（P0 → P1 → P2，同级成本 S → M → L）；可依批次上下文调整取哪
   项，但**跳序必须在提交信息里说明理由**——否则「顺序」会慢慢沦为摆设。
2. **偿还 = 从本表移除该行**，同时在《优化落地记录.md》记批次详情。
   表只变短不变长是唯一健康信号；行数长期不动，说明规则没被执行。
3. **发现新债务当天记录到本表**（哪怕当批不修，给个 ID 即可）。
   「债务只增不减」的根因是发现不上账，不是修得慢。
4. 批量处置时优先**同源项一起还**（如 D1 与 A3 是同一问题的短期/长期解），
   避免刚还一项又被它的长期版挡住。
