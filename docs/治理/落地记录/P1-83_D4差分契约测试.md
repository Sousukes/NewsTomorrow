D4 的结论是**不消除 mock**（它承载「不起后端就能跑」），而是补上「两份实现之间
无人比对」这个真缺口。设计见 `docs/后端/D4消除mock第二实现.md`。

## 交付

| 文件 | 内容 |
| --- | --- |
| `scripts/contract-diff.mjs`（新） | 同一份请求清单打 mock 与真后端，比对 HTTP 状态、业务 code、**响应形状**（字段集合 + 类型 + 嵌套结构） |

## 第一次运行就抓到 3 处真实漂移

这不是演示用的脚手架，是当场发现了问题：

| 漂移 | 性质 | 处理 |
| --- | --- | --- |
| mock 公开接口下发了 `hotScore` / `publishedAt` | **真问题**：管理端字段不该出现在公开接口（热度分下发等于把排序权重交给刷子） | 修 mock（`publicNews` 剔除） |
| mock 公开接口缺 `cover` / `videoUrl` / `playCount` / `isTop` | **真问题**：真后端固定下发（值为 null），mock 直接省略——形状不一致 | 修 mock（补齐 null） |
| `sourceKey`：mock 是 string、真后端是 null | **有意差异**：mock 用 `mockSourceKey(名称)` 合成，让离线演示能展示「关注」；真后端种子资讯的来源（新华社等）不在 RSS 源表里 | 声明为已知差异 |

第三条进了 `KNOWN_DIVERGENCES`（脚本内）+ mock 文件头的「刻意不模拟」清单——
两处必须同步，新增漂移仍会红。

## 四个设计决定

1. **只比形状，不比取值**：id、时间、条数必然不同，比的是字段集合/类型/嵌套结构。
   数组按**元素形状**比（`$.data.list[]`），不比长度。
2. **任一端不可达 → 跳过并退出 0**：不把本地主流程绑死在「必须同时起两个服务」上；
   CI 里用 `DIFF_REQUIRE_BOTH=1` 变成硬失败。
3. **已知差异必须写理由**：`KNOWN_DIVERGENCES` 每条强制带 `reason`，
   否则这里会慢慢变成「什么都能塞」的垃圾桶。
4. **不动 3052 行的 `contract-check.mjs`**：那个验「前端期望 vs 某一端」，
   这个验「两端彼此一致」，职责不同，硬合并只会让两边都难改。

## 两个自己踩的坑

1. **报错文案把两边说反了**：`diff(a, b)` 的 `a` 是 mock，但文案写成「仅 mock 有」——
   会把排查引向错误的一侧。已改为「仅真后端有（mock 缺）」。
2. **空数组被误判为「一边不是数组」**：`shapeOf([])` 的元素形状是 `null`，
   而我把 `null` 当成"非数组"信号。改为：两边都空视为一致，只有一边空才提示。
