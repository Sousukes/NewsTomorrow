## 批次 P1-25（2026-10-17）：消息已读越权防护（H11）
- **背景**：本批次起点是全库架构审查（产出 `docs/review/
  architecture-review-2026-10-17.md`）。该审查逐条复核了 10-11 那轮
  `open-code-review` 的 11 项 High，**确认 7 项至今未修复**——功能侧连推 9 个
  批次（P1-16~P1-24）而债务侧零偿还。H11 是其中唯一可被直接利用的数据泄露入口，
  故作为批次 A「止血」的第一项。
- **问题三层**（同一行代码里叠了三个洞）：
  1. **鉴权**：依赖是 `get_current_user_optional`，docstring 写「需登录」而实际
     匿名可调用；
  2. **可见性**：`db.get(Message, message_id)` 直接取行，随后返回
     `title` / `summary` / `newsId`——任何用户凭 id 即可读**他人定向消息**全文，
     而种子 id 形如 `m1..m4` 可直接枚举；
  3. **响应码**：不存在的消息返回 **200 静默成功**，于是「标记了一条不属于你的
     消息」在响应上表现为成功——**越权与否完全不可观测**，也就没人会发现它。
- **修复**（`routers/messages.py`）：依赖改 `get_current_user`（未登录 40100）；
  查询改为 `filter(Message.id == id, visible_condition(user))`，**先按可见范围过滤
  再操作**；不可见与不存在**同码 40400**——与资讯软下架（`hidden` 与「不存在」
  同码）同一条口径：对外不暴露「它存在但你看不到」。
- **契约变更**：`PATCH /api/messages/{id}` 消息不存在由 200 → **40400**。
  旧用例 `test_mark_missing_message_is_noop`（断言 200）就地替换为
  `test_mark_missing_message_is_404`——**契约变了，断言必须跟着变，不能留着
  旧断言假装没变**。
- **前端配套（两处，缺一即回退为体验事故）**：
  - `stores/messages.ts`：无登录态时 `markRead` / `markAllRead` **只落本地、
    不发起写请求**。后端此时会 401，而 `api/http.ts` 的 401 处理会广播
    `mingri:unauthorized`，`main.ts` 监听后 `router.push('/login')`——
    **游客点开一条消息就会被踢到登录页**。
  - `api/http.ts`：`handleUnauthorized` 改为**仅在原本持有 token 时**广播事件。
    这是兜底：任何「需登录接口被游客命中」的场景都不该被当成会话过期处理。
- **测试**：后端 586 → **591**（新增 `TestMarkReadAuthorization` 4 项：收件人
  本人可标记、**他人标记 40400 且响应体不回显任何字段也不写已读关系**、广播消息
  任何登录用户可标记、**越权尝试不影响他人未读数**；`TestMessages` 另增契约变更
  2 项）。前端 467 → **469**（游客 `markRead` 不发起请求、游客 401 不广播事件）。
- **踩坑一（响应码本身就是安全面）**：修越权时只盯着「能不能读到」是不够的。
  原来「不存在 → 200 静默」让越权行为在日志与响应里都表现为成功，等于**没有
  可观测性**；改成 40400 后，越权尝试直接变成一条 4xx，告警与审计才有着落。
- **踩坑二（收紧后端鉴权必须回看前端全局副作用）**：后端加 `get_current_user`
  只是把 401 从「不会返回」变成「会返回」，而前端对这个状态码挂了**全局跳转**。
  凡是「收紧某个端点的登录要求」，都要反问一句：游客会不会走到这条路径？
  走到之后会不会被全局处理器当成登录态失效？——**局部鉴权变更 × 全局副作用**
  是本类修复最容易漏的一侧。
- **迁移**：无（不触碰表结构；错误码复用既有 **40400**）。
- **回归**：后端 pytest **591 全绿**；前端 vitest **469 项**（25 个文件）全绿。
- **文档**：后端 README（消息中心章节补 H11 说明与前端配套、接口清单

  游客行为、`api/messages.ts` 标注）；速查表（汇总表 P1-25 行 + P1-25 详情节）；
  本记录。
