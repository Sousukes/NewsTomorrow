## 批次 P1-14（2026-10-15）：管理员白名单应用内管理（指定账号）
- **背景**：后台能力此前只由 `ADMIN_PHONES` 环境变量承载「指定账号」——加/撤一名管理员要改
  部署配置并重启服务，运营无法自助。用户提出「源管理界面设置权限，指定账号才能访问」时，
  现状是**已经有**指定账号门控（env 白名单 + `isAdmin` 下发），缺的是「应用内可改」。
  经确认后按「DB 化白名单」方向落地。
- **双源并集判定**：`admin.is_admin(phone, db)` 改为 **`ADMIN_PHONES` ∪ `admin_users` 表**——
  env 保留为 break-glass（改配置重启即生效、不依赖库可用），库白名单供日常运营（增删即时生效），
  **两边都为空 = 整体关闭**（生产安全语义不变）。判定的调用面同步收口：
  `/api/news/refresh`、`/api/admin/*`、以及登录/注册/续期响应里的 `isAdmin` 全部走同一函数，
  db 透传到 `_token_payload`（避免了「续期后标志不跟随库变动」的分叉）。
- **预授权**：`admin_users.phone` 作主键且**不设 users 外键**——账号尚未注册也可先加入名单，
  其注册/登录时 `isAdmin` 即为 true；列表行带 `registered` 区分「已注册 / 预授权」并回显用户名。
- **末位保护**：移除管理员时，若移除后任何来源都不再有任何管理员，返回 40904——
  否则生产环境可能把自己锁在门外，只能改环境变量重启来恢复。
  「env 非空时库中最后一条仍可移除」是刻意的对照面（env 就是应急通道）。
- **审计**：`added_by` 记录操作者手机号，回答「谁能授权」的追问。
- **前端**：新增 `/admin/users`（`views/AdminUsers.vue`）——双源说明卡（披露 env 管理员**数量**、
  不下发号码）、添加表单（手机号 + 备注、前端同规则预校验）、白名单列表（注册状态 / 备注 /
  添加者 / 时间）、移除二次确认；入口在个人中心与源管理页页头两处可达；`api/admin.ts` 补
  `fetchAdminUsers` / `addAdminUser` / `removeAdminUser`，行数据经 `toAdminUser()` 归一化
  （形态非法的手机号直接丢弃——删除按 phone 定位，脏行无法操作）。
- **mock 后端同步**：内存白名单 + `isAdminPhone` 改为同款双源判定，`/admin/users` 三端点与
  错误码（40903 / 40904 / 40403）保持一致，`dev:api` 模式可完整体验。
- **踩坑（真 bug）**：`_admin_out` 初版用 `db.get(User, row.phone)` 判断注册状态——
  **`User` 主键是自增 `id` 不是手机号**，拿手机号当主键查会永远返回 None，`registered` 恒为 false。
  是 `test_registered_flag_flips_after_register` 这条断言把它逼出来的
  （另两条「尚未注册」的用例因预期恰为 false 而不会失败）。改用 `filter(User.phone == ...)`。
- **踩坑（测试写法）**：
  1. f-string 里嵌套双引号（`f"Bearer {r.json()["data"]["token"]}"`）在当前的 Python 上解析失败
     ——改为先取 `login` 变量再 `f"Bearer {login['data']['token']}"`；
  2. 「移除后行已移出列表」初版断言 `not.toContain('13900000002')`，被 toast 文案
     「已移除 13900000002」命中而误报——改用列表项计数 `.admin__item` 与空态文案断言；
  3. `cd X && python -m uvicorn ... & SRV=$!` 会把**整条 `&&` 链（含 cd）**丢进后台，
     后续命令在错误 cwd 下报 MODULE_NOT_FOUND——后台只包单条命令 + 绝对路径（第二次踩同一个坑）；
  4. 契约脚本初版临时管理员手机号取 `22644212515`，不以 `1` 开头被 422 拦下，改为合规号码。
- **应急通道缺失的软提示**：生产环境 `ADMIN_PHONES` 为空时**不阻断启动**（库白名单本身是完整的
  日常通道），但三处可见：启动日志告警、`/api/health.adminBreakGlass=false`（只下发布尔值）、
  管理员页整张双源说明卡转红色并说明风险（DB 故障 / 行被误删 / 迁移回滚时它是唯一入口）。
- **测试**：后端 253 → **268 项**（新增 `TestAdminWhitelist` 13 项 + `TestAdminFlagInAuthPayload` 1 项
  + `test_migrations` 1 项）；前端 203 → **212 项**（`views/AdminUsers.spec.ts` 9 项）；
  契约 47 项（`CHECK_ADMIN=1` 时 56 → **65 项**，mock 与真实后端 PG 各跑一遍均 65/65）。
- **迁移**：`0015_admin_whitelist`（`admin_users` 表，`ix_admin_users_created_at`）；
  PG 库已追平，`alembic check` 无漂移。
