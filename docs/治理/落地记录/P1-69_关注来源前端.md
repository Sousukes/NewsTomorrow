## 六个实现要点

1. **关注流不是 channel**：`HOME_TABS` 是 UI 级组合，`ListKey = Channel | 'following'`。
   `CHANNELS` 仍是频道唯一来源，不被污染——否则后端校验运营频道时会多一个非法选项。
   store 的桶表按 `ListKey` 编排，关注流因此复用了既有的分桶与代次守卫（A4）。
2. **`feed=following` 时不传 `channel`**：服务端会忽略 channel，但带着它会在调试时
   误以为能组合（"关注 + 科技"没有这个语义）。请求侧与测试都钉住这一点。
3. **离线分支 = 同一契约的本地实现**，不是假数据：`{ keys, list }` 形状、幂等、
   上限 200、未知源报错全部一致。store 层因此不判断模式，契约漂移直接表现为 UI bug。
4. **`sourceKey` 由名称哈希派生**（`utils/source.ts`）：离线演示没有源表，
   但"关注"要在默认模式可用。哈希而非自增下标——数组顺序一变，自增 key 就会指向别的源。
5. **没有 `sourceKey` 就不渲染作者区**：关注按钮依赖 key，缺 key 还显示按钮就是死按钮
   （`AppNav` 的「更多」刚因同样原因被修过一次）。
6. **关注是账号数据，不排本地**：未登录时只有登录门禁，没有"匿名也能关注"的分支。
