## 批次 P1-13（2026-10-14）：源管理界面增强（搜索筛选 / 健康汇总 / 批量操作）
- **背景**：P1-10 交付的源管理页在源少时够用；内置 + 自定义源到几十个后，
  三个痛点变得真实：**找不到源**（只能滚动肉眼扫）、**不知道哪个源挂了**
  （异常源混在权重序里）、**批量运营无处下手**（换频道要逐个点开关）。
- **搜索与筛选**：名称 / 地址 / 标识（key）三处模糊匹配（大小写不敏感）；
  频道 chips（全部 + 7 频道，横向滚动）+ 状态 chips（全部 / 启用中 / 已停用 / 异常 / 未抓取）；
  筛选无结果时给「没有匹配的源 + 清除筛选」，不呈现死胡同。
- **健康汇总与异常置顶**：汇总区从「启用数/总数」升级为**四计数**
  （总数 / 启用中 / 异常 / 未抓取），且**计数即筛选入口**——点「异常」只看异常源，再点取消；
  异常源**自动置顶**（稳定排序：组内保持后端权重降序，只把异常提前）——
  「哪个源挂了」应该是打开页面第一眼看到的信息，对应「未纳入本轮」里
  「超时未成功告警」的前置部分。
- **批量操作**：「批量管理」进入多选模式（checkbox + 行点选 + 全选）；
  **全选只作用于当前可见项**（筛选后的批量才符合直觉）；
  批量启停 / 批量删除复用现有 `updateSource` / `deleteSource`——**串行逐个调用**
  （几十个源的量级串行够快，且避免并发打满后端）；
  批量启停先本地乐观翻转、失败项还原并汇总报错（"N 个源操作失败，已还原，请重试"）；
  批量模式下隐藏单项编辑/删除/开关，两种交互不叠加。
- **顺带修复**：`toast` 此前**永不过期**（设置后不清空）——批量操作会频繁触发提示，
  补 3s 自动消失；另修复 P1-12 遗留的 **prettier 格式债**（`comments.ts` / `Comments.vue` /
  `contract-check.mjs` 三个文件 + 本次新文件，`npm run verify` 的格式检查段此前后一直被
  eslint 失败短路掩盖，P1-12 修完 eslint 后才暴露）。
- **踩坑（测试侧）**：写「全选只作用于可见项」用例时第一版断言写错
  （取消全选后仍剩 1 项选中，再全选自然是 3 项）——**组件行为是对的，是测试预期错了**；
  改为「先筛选再全选 + 清除筛选后范围外项仍未选中」才真正验证到语义。
- **测试**：前端 193 → **203 项**（`views/AdminSources.spec.ts` 10 → 20：
  搜索三路命中与无结果清除、频道/状态筛选、四计数与点击筛选/再点取消、
  异常置顶且组内保序、批量进入/全选可见项/批量启用成功清空选择/
  部分失败回滚（退出批量后核对开关态）/ 批量删除确认与移出、批量模式交互不叠加）。
  后端无改动（253 项保持）；契约 47 项保持（无接口变更，mock 复跑 47/47）。
- **迁移**：无（纯前端，复用 P1-9/P1-10 的五个管理端点）。
