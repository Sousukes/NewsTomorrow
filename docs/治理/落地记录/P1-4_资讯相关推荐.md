## 批次 P1-4（2026-10-11）：资讯相关推荐（路线图第 3 项）
- **问题**：详情页是终点，读完没有出口，停留时长与点击深度都受影响。
- **改动**：新增 `GET /api/news/{id}/related?limit=6`，三级召回逐级兜底：
  1. **标题相似度**：PostgreSQL + `pg_trgm` 时用 `similarity(title, 当前标题)` 召回，
     阈值 0.05 过滤噪声；
  2. **同频道最新**：不足时补齐（也是 SQLite / 无扩展时的主策略）；
  3. **全站最新**：仍不足时兜底。
     始终排除自身、按 id 去重、`limit` 限定 1–20（越界 422）。
- **关键细节**：`pg_trgm` **必须运行时探测**——迁移 0005 在权限不足时会跳过建扩展，
  SQLite 根本没有 `similarity()`，无条件调用会直接报错。探测结果进程内缓存。
  这样既复用了 P0 已落地的索引投入，又不会在无扩展环境崩掉。
- **前端**：`api/news.ts` 增 `fetchRelated`（**失败静默降级为空数组**，不影响正文阅读）；
  `NewsDetail.vue` 正文下方新增「相关推荐」区块，复用 `NewsCard`。
- **实测**（真实库，pg_trgm 已启用）：`新能源汽车出口…` → `宁夏新能源日发电量创新高`
  （命中"新能源"三元组），证明相似度召回真实生效；无相似标题时自动退回同频道/最新。

  404 / 前端字段形状 / 无重复 / 同频道优先且兜底补齐）；
  前端 91 → **96 项**（新建 `src/api/news.spec.ts` 5 项）。
