## 四个实现要点

1. **代际守卫**是联想链路的地基而非优化：连续输入时慢请求先回来会覆盖新结果，
   表现为「下拉的词落后于输入」。`async` 里捕获代次、回来时不等就丢。
2. **debounce 280ms**：低于 200ms 等于逐键请求，高于 400ms 用户已等到失去耐心。
   清空输入时**先废掉代次**再清列表，避免在途请求回来又弹出一个空下拉。
3. **纠错项单独标注**「您是不是想搜」：它解决的是"输入就错了"，
   与"更多候选"是两种意图，混在同一个列表里会让用户分不清该不该点。
4. **联想失败静默降级**：它是输入过程的辅助，坏掉不该让搜索本身不可用
   ——与热搜词同一取舍，但**提交路径必须仍然可用**（有专门测试）。

## 对后端契约的两处前端侧承接

- **`limit` 越界不在前端夹取**：mock 与真后端都会 422，夹取了就永远测不出参数错误；
- **`kind` 缺省归一到 `title`**：后端若新增第四种 `kind`，前端按标题样式渲染而不是崩
  （类型上仍是受控联合，归一化在 api 层完成）。

## 测试（15 项）

- `api/news.fetchSuggestions`（4）：空输入不请求、路径与参数、缺字段归一、失败降级
- `Search` 联想（8）：debounce 合并为一次请求、**慢请求不覆盖新输入**、点建议直接跳转 + 记历史、
  纠错标注、清空收起且不发请求、失败不影响提交、空结果不渲染空面板
- `SearchResults`（3）：零结果给热搜入口且点击换搜索、热搜拿不到仍保留换词入口、有结果不显示引导
