## 批次 P1-12（2026-10-14）：二级评论 + 点赞关系表化
- **问题**：① 评论只有一层——想回复某条回复只能再发一条主评论，"回复 @谁"的语境丢失；
  ② `comments.liked_by` JSON 数组随点赞无上限膨胀，无法按用户高效判定（全量拉取解析），
  也建不了复合索引——`message_reads`（0004）已示范过关系表方案，本条为剩余项。
- **迁移 `0014_comment_likes_and_replies`**：
  - `comments` 增 `parent_id`（被回复者）/ `root_id`（所属主评论，NULL = 主评论），
    均带**自引用外键**（仅 PG 建，与 0003/0007/0010 同策略）+ `ix_comments_root_id`；
  - 新建 `comment_likes`（`(comment_id, user_id)` 复合主键 + 内联 `ON DELETE CASCADE` 外键）；
  - Python 端回填：先取 `valid_users` 集合防 PG 外键炸库，seen 集合去重，跳过悬空/非整数
    user_id；回填后 `UPDATE comments SET likes = (SELECT COUNT(*) …)` 对齐冗余计数；
    batch 模式删 `liked_by` 列。downgrade 可逆（PG 回填用 `CAST(:p AS JSONB)`）。
  - **验证**：SQLite 链 14/14（含数据往返）；PG **影子模式** 12/12 PASS——
    无 CREATEDB 权限，用 `PGOPTIONS="-c search_path=mig_check,public"` 把整条迁移链重定向到
    临时 schema（search_path 带 public 是为让 `gin_trgm_ops` 可解析；**必须预建空
    `mig_check.alembic_version`**，否则 alembic 读未限定模式名的版本表落到 public（已 0013）
    导致整链 no-op）。覆盖回填去重/悬空/非整数、计数对齐、自引用外键、**删主评论级联删回复
    端到端**、downgrade 还原。常驻脚本 `scripts/verify_comment_likes_migration.py`；
    开发库已追平，真实回填 44 条评论 / 23 点赞行 / 0 漂移。
- **后端**：
  - `models.Comment` 删 `liked_by`、新增父子列；`CommentLike` 仿 `message_reads`，
    **不建 ORM relationship**（软删除无对象图可级联，文档说明）；
  - `to_out` 增 `parentId/rootId/replyCount/replies/replyToName/replyToUserId`；
    `_decorate_roots` 用**窗口函数** `row_number() OVER (PARTITION BY root_id ORDER BY
    created_at, id)` 取每组最早 2 条预览（不把全部回复捞进内存）；`_liked_ids` 一次 IN 查询
    覆盖主评论 + 预览回复（无 N+1）；
  - 新端点 `GET /{news_id}/comments/{cid}/replies`：时间**正序**（讨论先后）游标分页，
    root 缺失/已删返回空列表——主评论消失后失去语境的回复不再裸露；
  - `create_comment`：parentId 校验（不存在/跨文章/已删 → 40003），
    `root = parent.root_id or parent.id` 拍平；**回复只通知被回复者**
    （`notify_comment_replied`），不走广播（避免同一个人收两条语义重复的消息）；
  - `set_like` 改走关系行插入/删除 + `likes` 同步，liked 取操作后真实状态。
- **前端**：
  - `types/validate/api` 接新字段；`listRepliesPage` + `createComment(newsId, content, parentId?)`；
  - `stores/comments` 重写：`byArticle` **只存主评论**；`replies` 为**单一数据源**——
    既是列表接口的「最早 2 条预览」，也可被 `loadReplies` 替换为完整列表（不维护两份拷贝）；
    `repliesMeta[rootId]` 记录游标状态；`reply()` 乐观插入 + 服务端返回后替换 + 失败回滚；

  - `Comments.vue` 展平行（主评论 + 可见回复，末条带「更多」）、回复框跟随目标、
    「回复 @谁」前缀；mock 种子改两级结构；
