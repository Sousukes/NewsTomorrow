## 批次 P1-48（2026-10-18）：管理端页面样板抽取（D3）

偿还 backlog 工程债组的 D3（M）。8 个 Admin 页面共 6,094 行，
`load/error/denied/toast/筛选/分页` 样板逐页复制。

## 先摸差异，再决定抽什么

上一批的经验是「先量再动」，本批先做了差异清单，结果**原计划的
`usePagedList` 通用分页被否掉**：

| 页面 | 分页形态 |
| --- | --- |
| AdminNews / AdminComments | 服务端 `nextCursor` + `hasMore` + `total` |
| AdminAudit | 服务端 `nextCursor` + `hasMore`（无 total） |
| AdminNicknameReviews | **offset + `list.length < total` 推断**，无游标 |
| AdminWords / AdminNicknameWords | 主列表不分页，**第二个列表**（命中日志）才分页 |
| AdminSources / AdminUsers | 不分页（要全量） |

强行统一就得写 `mode: 'cursor' | 'offset'` 开关，再加「是否第二个实例」开关——
那是个塞满 if/else 的四不像。**不适用就不该用**：最终 composable 只承诺
**游标分页**，那个 offset 页面保留自己的 `loadMore`。

## 抽了什么

`src/composables/useAdminPage.ts`：

- **`messageOf(e, fallback)`** —— 错误文案提取，原先 8 页各写 2 行；
- **`useAdminGuard()`** —— `denied` / `noAccess` / `handleError` / `resetDenied`，
  **8 页全部接入**。403 与「无权限」文案的判定收敛到一处；
- **`useAdminList<T>()`** —— 列表状态机（游标分页）：**3 页接入**
  （News / Comments / Audit），带按 id 去重与**代次守卫**。

**没有抽 `<AdminTable>` / `<FilterBar>`**：表格列与交互差异远超想象——
`AdminSources` 1,467 行里塞着健康趋势图、批量操作、统计卡与行内开关，
硬统一的结果是一个塞满 slot 与 prop 的空壳，比现在更难读。
**本批只抽行为，视图层的相似留给真正要改样式时顺手做**——明确不做并写明理由，
比做一个没人用的组件强。

## 迁移前后的行数

8 页合计 **6,094 → 6,022 行**（省 72 行），但真正的收益不在行数：
8 处相同的守卫逻辑与 3 处相同的列表状态机现在只有一份实现，
下一个人加管理页时不必再抄一遍——**抄错一处守卫就是一个越权面**。

## composable 自己抓到的两个 bug

写测试时发现的，都不是"重构没做对"，而是**这类状态机的固有坑**：

1. **`loadingMore` 会被过期请求卡死**：代次守卫让在途的旧 `loadMore` 整体作废，
   但它的 `finally` 因代次不符而**不清标志** → 翻页永久卡死。
   修法是 `reload` 启动时**主动接管** `loadingMore`。
   这正是门店页（A4）踩过的坑，同一个错误值得同一个解法；
2. **游标原地不动 = 无限翻页**：服务端把同一个游标再发回来时，
   「本页有新数据」也不会推进，翻页会一直转。
   改为：**游标不前进或没有新游标即停止**。

另外把 `hasMore` 的判定从"参数化的 `resolveHasMore`"改回**只用服务端的**——
三页都从服务端拿，那个参数是多余的通用性（而 NicknameReviews 用不上）。

## 迁移过程中的两个脚本坑

1. **正则匹配前必须逐条核对形状**：批量迁移 5 页时，`const denied = ref(false);`
   上面的**注释文案各页不同**（「不具备管理能力」/「不在任何白名单来源中」，
   有的还没注释），导致 4 页留下重复声明、编译期才炸；
2. **解构收敛要排除注释**：判断 `denied` 是否还被用到时，注释里的
   「转成 denied」被算成引用，于是留下未使用变量（`vue-tsc` 报 TS6133）。

## 维护约定

- 管理页统一用 `useAdminGuard()`，**不要**自己写 `isAdmin` 判定与 403 文案匹配；
- 列表**确实走游标分页**时才用 `useAdminList()`；offset/多列表的页面保留自己的状态
  （硬套会得到一个"够用但要靠开关"的四不像）；
- 页面里**不要**再定义本地 `message()`——从 `useAdminPage` 导入。
