## 六个实现要点

1. **单端点而不是 5 个**：大盘是一次性渲染的面板，拆 5 个就是 5 次往返 + 5 个
   loading 态；而且单端点才能保证**同一时间口径**——否则页面会出现"总量按 7 天、
   趋势按 30 天"的割裂，而这种割裂在运营眼里就是"数字对不上"。
2. **`days` 单一且收敛**：默认 7、`Query(ge=1, le=365)` 拦 0/负/超上限，
   `window_days` 把 31~365 收敛到保留期 30——与单源趋势端点同一处方，
   两个端口的 days 语义不会分叉。
3. **源健康复用 `summarize_many`**（P1-19 为防 N+1 写的单条 GROUP BY），
   Python 侧按失败率排序取 Top 5。"不健康"的定义是**有尝试且有失败**：
   没有尝试的源是空闲（礼仪跳过 / 熔断 / 未启用），算进 unhealthy 会让数字失去意义。
4. **按天分桶走 SQL 侧 `substr(col, 1, 10)`**：这些列是 `String(30)` 存 UTC ISO
   （全库唯一例外是 `health_events.at`），PG 与 SQLite 的 substr 行为一致。
   D1-2 打算把 `hit_logs.*` 迁成 DateTime，所以必须配 PG 护栏。
5. **不缓存**（D5）：管理端大盘低频（一天几次），缓存收益极小；而审核量是运营
   **决策依据**，陈旧比慢更糟。与 P1-62「热门列表评估后刻意不做」同款决策。
6. **mock 的数字全部从自身状态推导**，不写死——否则演示时改了一条数据大盘不动，
   反而像坏了。两个 mock 不建模的队列（举报复核）给 0 并在注释里说明。

## PG 护栏在第一轮就抓到一个真 bug

`TestDashboardOnPostgres` 直连 PG 跑一遍趋势与源健康查询。第一轮运行即失败：

```
operator does not exist: timestamp with time zone >= character varying
```

根因是我在 `source_health_block` 里**手写了 ISO 字符串作为 cutoff**，而
`rss_source_health_events.at` 是 DateTime 列（D1-1 迁移 0030）——PG 上
`timestamptz >= varchar` 直接报错，SQLite 不报、单测全绿。**与 P1-74 同款事故**，
而且是在同一批里、由同一个护栏抓住的。

修法不是就地改成 datetime，而是把 `health._since` **公开为 `since`** 供复用：
" N 天前的 UTC aware datetime，用于 DateTime 列参数绑定"这个口径只应有一份定义，
它本来就被 `tests/test_time_contract.py` 盯着。在 metrics.py 里再抄一行，
就是给下一处漂移留门。

第二轮护栏又抓到一个：PG 比 SQLite 严格——SELECT 与 GROUP BY 里的 `substr(...)`
若不是**同一个表达式对象**（分开写两次会产生不同的参数占位符），PG 认为
"未分组列"直接报 `GroupingError`，而 SQLite 静默接受。改为复用同一个 `day` 变量。

护栏已做**反向变异验证**：把 `created_at` 强制 cast 成 DateTime（模拟 D1-2 迁移后的
查询形态），PG 护栏以完全相同的生产错误
`function substr(timestamp with time zone, integer, integer) does not exist` 变红。

## 测试（16 项）

- 端点契约：5 板块齐全、`days` 回显与收敛（90 → 30）、0/负/999/abc 在校验层被拒
  （42200）、未登录 401 / 非管理员 403、**空库不炸**（全 0 / 空列表）
- 口径护栏：`news` 与 `newsHidden` 分开数；下架量按 `hidden_at` 过滤而非"当前是否
  隐藏"（恢复过又隐藏的不漏、历史上架过的不算）；`todo.reports` 只数 `pending`
- 源健康：按失败率**升序**（断言顺序而非成员包含）、Top N 截断、空闲源不计入
  unhealthy、`avgItems` 按成功轮次均值（失败轮次的条数不会把均值抬起来）
- 命中趋势：按 UTC 天分桶、升序、两序列齐全、窗口外不计
- 纯函数：`now` 注入后 `generatedAt` 跟着走（可回放）
- PG 护栏：见上

## 刻意不做

- **图表库**：管理端是内部工具，引一个图表库的收益不抵它的体积与暗色模式适配成本。
- **实时推送**：大盘是"打开看一眼"的页面，WebSocket/轮询是为"盯着看"设计的。
- **进程指标入大盘**：`/api/metrics` 继续服务 Prometheus（它是文本格式 + OPS_TOKEN）。
- **自定义时间范围**：`days` 只有预设档，自由日期选择会引入"起止 + 时区"一整类问题。
