## 批次 P1-33（2026-10-18）：时间基准统一（A3）
backlog 规则生效后的第一批：偿还最上方的 A3（P0 遗留，与 D1 同源）。

**现状比审查报告写的更糟**：全库混着**三种**口径——`now_str()` 写本地
naive（绝大多数列）、`ranking._iso_seconds` 写 naive-UTC（`hot_score_at`）、
抓取/种子写 aware-UTC（`published_at`）。「同格式 ISO 的字典序即时间序」
这条契约因此不成立：字符串排序与真实时间序脱节，读侧 `_to_naive_utc`
把本地时间按 UTC 解释，衰减计算有整小时 skew（`hot_score_at` 列的两种
写法还自相矛盾——bump 写 naive 本地、重算写 naive-UTC）。

- **写入侧**：`now_str()` → `datetime.now(timezone.utc)`（`+00:00` aware）；
  新增 `models.parse_dt()` 作为读取侧唯一入口（aware→UTC、naive **按 UTC
  解释**——与回填口径必须一致，否则回填后各说各话、脏值 None）。
- **比较侧全量排查**（本批最容易漏的地方：所有字符串比较都要求同格式）：
  - `ranking`：`_to_naive_utc` → `_to_utc`（naive 按 UTC 解释，与测试锚点
    同口径，用例零改动）、`_iso_seconds` 输出 aware、`now` 默认值 aware；
  - `health.prune` / `_since`、`search_stats` 三处窗口、`sources.next_retry_at`
    写入、`alert._parse`（归一）与两处 `now`——全部改 aware；
  - `ingest._too_soon` / `_circuit_open` 本就按 `dt.tzinfo` 自适应、
    `me.py` 本就 aware（`_now_iso` + `_parse_iso`）——**不动**，这是排查
    时特意确认的，避免顺手改出 bug。
- **迁移 0027**：17 张表约 30 个时间列回填，**只补偏移、不改数字**。
  为什么不按本地时区 +8h：存量 naive 来源不可恢复——`hot_score_at` 存量
  本就是 naive-UTC 数字（移位会错），其余列是写入机器的本地时间（时区
  无法反推）。补偏移保住唯一能验证的性质：**相对顺序精确保留**；绝对值
  偏差有界（≤ 时区偏移），48h 半衰期下影响小且自愈。date-only 补零点、
  `+08:00` 归一 UTC、脏值原样保留并计数；`*.time` 展示文案列白名单排除。
  downgrade 空操作（回填不可逆，不造假）。
- **测试**：新增 4 项格式单测（`now_str` aware/秒精度、`parse_dt` 三种输入）
  + 2 项回填迁移测试（混合 naive/`+08:00`/date-only/脏值 → upgrade → 逐值
  + 顺序断言）。全量跑出 3 处失败，**全是断言旧格式的用例**（`tzinfo is None`、
  naive 锚点、`datetime.now()` 算节流窗口）——逐一改成 aware 口径，
  不是放宽断言。**契约不变**（响应字段从 naive 变 aware 是内部口径，
  前端只透传展示）。
- **回归**：pytest 626 → **632 全绿**；PG upgrade 0027 + `alembic check`
  无漂移；真后端契约复跑 + 存量数据抽样核对。

  唯一入口 + 回填口径 + 不可逆说明）、速查表（汇总表 P1-33 行 + 详情节）、
  backlog（**A3 移行，31 → 30**）、审查报告（A3 标注）、本记录。
