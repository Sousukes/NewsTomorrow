## 批次 P0（2026-10-10 全量评估后的首批修复）
> 来源：2026-10-10 对前后端全量实现的系统评估（性能 / 结构 / 健壮性 / 安全 / 可维护 / 可扩展 / 测试）。
> 本批只做**低成本高收益**且能立即验证的 4 项；P1 及以后另批。

### P0-1 schema 单轨化（Alembic 唯一入口）

- **问题**：实测发现 `alembic current = 0003` 而 `heads = 0006`——`message_reads` 表、
  `users.token_version` 列、`ix_news_feed` 复合索引、pg_trgm 搜索索引**在库里都不存在**。
  根因是 `app/seed.py` 的 `init_db()` 每次启动都跑 `Base.metadata.create_all()`，
  与 Alembic **双轨管理 schema**：create_all 补建的物件不写入 `alembic_version`，
  导致后续 `upgrade head` 会因"对象已存在"失败，且各环境结构分叉。
  连带后果：批次 H/M 已交付的 `ix_news_feed` 与 pg_trgm 索引**实际未生效**，feed 排序与搜索仍在全表扫描。
- **改动**：
  1. 执行 `alembic upgrade head` 把本地 PG 库从 0003 追平到 0006（66 条数据无损）；
  2. `app/seed.py` 新增 `_assert_schema_ready()`：**只校验不建表**，缺表时抛 `RuntimeError`
     并给出可执行指引（`alembic upgrade head`）；移除 `init_db()` 中的 `create_all()` 与随之无用的 `Base` 导入。
- **迁移**：`0004` / `0005` / `0006` 本轮首次真正应用到数据库。
- **测试**：`tests/test_hardening.py` 新增 `TestSchemaSingleTrack`（2 项）——
  空库调用 `init_db` 抛错且**未就地建表**；源码层面断言 `init_db` 不含 `create_all`（防回归）。
- **文档**：README「快速开始」补 `alembic upgrade head` 步骤；「数据库迁移」章节说明单轨制与移除原因。

### P0-2 补齐依赖声明

- **问题**：`app/ratelimit.py` 会 `import redis`、`.env.example` 也写了 `REDIS_URL`，
  但 `requirements.txt` **未声明 redis**——配置了也只会静默回退进程内限流，
  运维会误以为多实例限流已启用；`pytest` 同样未声明，干净环境装完依赖跑不了 88 项测试。
- **改动**：`requirements.txt` 增加 `redis>=5.0`（标注为可选）与 `pytest>=8.0`；
  `build_limiter()` 回退日志补充"多实例限流将不一致，请检查 redis 依赖与连接"，不再静默。
- **迁移/测试**：无（行为由既有回退测试覆盖）。

### P0-3 修复轮播克隆帧重复 key

- **问题**：`useCarousel` 的轨道为 `[末帧, ...全部, 首帧]`，首帧与末帧各出现两次，
  而 `BannerCarousel.vue` 用 `:key="id"` → Vue 重复 key 告警，且 patch 时可能错误复用 DOM
  （配图错位 / 过渡闪烁）。同时每帧渲染都 `items.find()` 取配图与标题（各一次），为 O(n²)。
- **改动**：`:key` 改为 `` `${id}-${i}` `` 组合键；新增 `itemById` computed 建 Map，
  `coverOf()` / `titleOf()` 改为查表。
- **测试**：新增 `src/components/BannerCarousel.spec.ts`（8 项），含**重复 key 回归用例**
  （监听 `console.warn` 断言无 `Duplicate keys`，并覆盖切换列表长度的 patch 场景）。
  已反向验证：把 key 临时改回 `:key="id"` 后该用例会失败，修复后通过——确认非空测试。

### P0-4 频道常量单一来源

- **问题**：频道取值硬编码在三处（`types.ts` 联合类型、`HomeFeed.vue`、`Showcase.vue`），
  新增频道需改三处且类型与数据可能漂移。
- **改动**：新增 `src/constants/channels.ts` 作为唯一来源：`CHANNELS` 派生出 `Channel` 类型、
  `CHANNEL_KEYS`、`DEFAULT_CHANNEL`，并提供 `channelLabel()` / `isChannel()` / `toChannel()`；
  `types.ts` 改为从该文件推导并透出（保持既有 `@/types` 引用路径不变）；
  `HomeFeed` / `Showcase` 改用常量，切换频道经 `toChannel()` 归一化。
- **连带修正**：`ChannelTabs` 原先 `key: string` 过于宽松，掩盖了 `Videos.vue`
  把「直播/影视/搞笑」子分类当作资讯频道使用的问题。现拆分为通用 `Tab`（key: string）
  与频道专用 `ChannelTab`（key: Channel），`ChannelTabs` 接受 `Tab[]`
  （`ChannelTab[]` 仍可赋值，因 Channel ⊂ string）。
- **测试**：新增 `src/constants/channels.spec.ts`（8 项）：key 唯一、标签非空、顺序一致、
  标签查表与未知回退、`isChannel` / `toChannel` 对非法输入的守卫。

### P0-5 顺带修复：契约检查脚本漂移

- **问题**：`scripts/contract-check.mjs` 对 `GET /news/:id/comments` 的返回值直接调 `.find`，
  但评论接口在批次 M 已改为游标分页（返回 `{ list, hasMore, nextCursor }`）→
  抛 `list.find is not a function` 并**中断后续所有检查**（此前一直静默失败）。
- **改动**：按 `/api/news` 同样的方式解包 `data.list ?? []`，并补注释说明原因。
- **测试**：修复后契约检查恢复 **12 / 12 全通过**。
