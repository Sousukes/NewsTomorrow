## 批次 P1-46（2026-10-18）：文档按专题拆分（F4）

偿还 backlog 工程债组的 F4（S）。**债务比审查时更大了**：审查记录的是
README 102KB / 落地记录 139KB，实际到本批已是
后端 README **137KB** / 前端 README 68KB / 落地记录 **217KB** / 速查表 **137KB**
（合计约 558KB）。

**问题不是"不好看"，是已经搜不动了**：在 2000 多行里找一个错误码要靠
Ctrl+F 全文件翻，编辑器跳转全靠滚动。而写新内容的人第一反应是"接着写在这篇里"——
于是它只会更长。

## 结果

| 文件 | 拆分前 | 拆分后 |
| --- | --- | --- |
| `server-api/README.md` | 137KB | **3.3KB**（入口：快速开始 + 索引 + 5 条最易踩约定） |
| `mingri-toutiao-vue/README.md` | 68KB | **3.1KB** |
| `优化落地记录.md` | 217KB | **27KB**（索引 + 汇总表 + 批次清单） |
| `明日头条-组件与接口速查表.md` | 137KB | **0.8KB**（纯索引） |
| `docs/` 下 | — | **64 篇**，最大一篇 45KB |

目录按**读者要找什么**组织，不按"哪个文件写的"：
`docs/{后端,前端,治理/落地记录,速查表,review}` + 总索引 `docs/README.md`。

落地记录**一个批次一个文件**（49 篇）。速查表里 29 个 `####` 批次详情也各拆一篇
——这一篇按 `## ` 拆完**仍有 128KB**，因为它的"章节"本身就是 29 个小节，
只切一层根本切不动。

## 用脚本拆，不手改

45+ 处手工搬运会漏内容，而 git diff 里看不出来。脚本按 `^## `/`^#### ` 切块
重写，并**报告未分配的章节**——第一版确实漏了 7 个后端章节（覆盖率门槛、部署、
昵称校验、错误码、时间口径等），是脚本喊出来的，不是人看出来的。

命名也踩了两次：先按 `批次 X` 提取前缀，结果 `## 批次 H（高优先级）` 的**整段
描述都在括号里**，剥掉括号就没了标题，产出 `H.md`；第二版又因为**先按冒号切再
剥括号**，切到了空串。最终版顺序是「剥括号 → 有冒号取冒号后 → 仍为空则回退用
括号内容并去掉日期前缀」。

## 拆分最怕的：链接断了而且没有任何症状

markdown 链接断掉只会渲染成普通文本，不报错、不进 CI。新增
`tests/test_docs_index.py`（**19 项**）把它钉住，第一次跑就抓到 **4 类断链**：

1. 索引生成时把 `docs/治理/落地记录/x.md` 截成了裸文件名（而索引在仓库根）；
2. 速查表索引同理；
3. **被搬动内容里的相对链接失效** —— 原文在 `server-api/README.md` 里写
   `../docs/deploy.md`，搬到 `docs/后端/` 后基准目录变了；
4. 一条指向**从未存在**的 `docs/news-fetch.md`（拆分前就是断的，顺手清理）。

护栏含三条硬约束：

- 全仓 markdown 内部链接必须指向真实文件（用 `unquote` 处理
  `API%20参考.md` 这类带空格的路径）；
- `docs/治理/落地记录/` 里每个批次文件都要被 `优化落地记录.md` 引用
  （漏挂一个 = 那个批次从此不可检索，而目录里明明有它）；
- **入口文档 < 40KB、任何单篇 < 60KB** —— 防"拆完又长回去"。这次拆分的目的是
  能搜，不是好看，只盯入口文件是不够的（细节文档同样会被人继续塞）。
