## 批次 P1-42（2026-10-18）：资讯列表热路径的两处性能债（B2 + B3）
转向 backlog 的**性能组**，偿还最上方两项（都是 S，且落在同一条热路径上）。

### B2：首页不再全表 `count()`

`GET /api/news` 的 `page` 改为**可选**：不传即走 keyset 分页，首页与续页同一套
查询，**不做全表 count**；显式传 `page` 才走旧的 offset 分支。

此前首页（还没拿到 cursor 时）落在 offset 分支里——**每次打开页面都做一次全表
`count()`，那条路径上的用户占比是 100%**。这不是「深分页才慢」的边角问题，
而是主路径。

保留 offset 分支是刻意的：仍需要「第 N 页 / 共多少条」语义的调用方存在，
直接删掉会让老客户端崩。`total` 变为 `null` 时前端回落 `list.length`——
用户侧界面本来就不消费列表的 `total`（只有管理端与搜索页在用），无可见影响。

**测试断言的是"不出现 COUNT 语句"，不是响应形状**：只把 `total` 改成 `null` 而
底下照样 `count()`，契约看不出差别，债原封不动留着。
`tests/test_list_perf.py` 用 SQLAlchemy 事件抓真实执行的 SQL 来守这条。

### B3：`for-you` 频道偏好缓存

`channel_preferences()` 原本是每请求两次 JOIN + GROUP BY，而一次翻页可能打
十几个请求——同一秒里算十几次完全相同的聚合。

- 新增 `app/cache.py`：进程内 / Redis 双实现，与 `ratelimit` 同一套口径
  （探活失败降级 + 只告警一次、**任何缓存异常都不许冒泡**、键前缀 `cache:`
  与限流的 `rl:` 分开）
- 缓存 5 分钟（`CHANNEL_PREF_TTL_SECONDS`）
- **失效优先于过期**：收藏/浏览/合并/清空的任一写入路径都调
  `invalidate_channel_preferences()`（键的拼法只在这一个函数里——散开写迟早
  拼错，而"拼错"的后果是缓存永不失效且**没有任何报错**）
- **空偏好不缓存**：那是"还没产生行为"的多数访客，缓存它只堆永不命中的键
- `CACHE_ENABLED` 在**调用时**读 `config` 模块属性；根 conftest 钉 false

顺带说一句：这个测试环境开关是**必须**加的，不是洁癖——每个测试文件都重建
sqlite、`user_id` 从 1 重新分配，进程内缓存会让上一个文件为「用户 1」算的偏好
被下一个文件的另一个「用户 1」命中，症状是 for-you 排序断言**只在全量跑时**
随机失败。

**mock 同步**：mock 的 `/news` 此前压根没实现游标（一直返回 `total`），
现按同一口径补上——不传 `page` 即 keyset 语义（用「偏移游标」实现：这里要验的是
契约形状，不是 keyset 本身的效率）。
