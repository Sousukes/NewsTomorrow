## 六个实现要点

1. **`recent_terms()` 必须共用**：热搜榜与联想各自写一份 `GROUP BY` 查询，迟早会出现
   「榜上是 A、联想里却没有 A」这种既难复现也难解释的漂移。现在两边同一个函数，
   `hot_terms` 只是它外面加了一层缓存。
2. **联想绝不写 `search_logs`**：联想是**输入过程**不是搜索行为。边打字就把
   「新能源汽」「新能源汽⻋」这类中间态写进榜里，热搜会被污染，而且词越长
   中间态越多、污染越严重。契约里有专门一条盯着它。
3. **纠错判据是「相似度 ≥ 0.3」或「编辑距离 ≤ 1」，取或**。这是本批**实测后对设计的
   唯一偏离**，理由见下节。
4. **正文不看 similarity**：无索引可吃的相似度表达式会让每条正文（单条可达 8000 字）
   都跑一遍三元组计算，收益远小于代价；只给 1 的命中权重。
5. **fallback 路径不加正文**（D2 定案）：那条路径的意义是「没有 trgm 时也能搜」，
   正文没有索引可吃，加进去会把扫描面扩大数倍，且两端排序口径会不对称——
   同一查询两端结果不同，比少召回几条更难解释。`test_fallback_path_does_not_scan_content`
   是这条决定的护栏。
6. **mock 的 limit 必须拒绝而非夹取**：夹取会让前端在 mock 上永远测不出「传错参数」，
   到真后端才吃 422。

## 对设计的一处偏离（已量出依据，不是随手改）

设计原文：纠错「对别人真实搜过的词做 `similarity` 排序」。**排序键仍是相似度**，
但**判定是否属于错字**改成了两条判据取或。原因是实测出来的：

- 三元组相似度必须做 **pg_trgm 的边界补齐**（两个前导空格 + 一个尾随空格）。
  不补齐时「近期词」与「近期祠」的三元组集合完全不相交，相似度恒为 0——
  短词纠错会整体失效。
- 补齐后，单个字替换会破坏 3 个三元组，**短词的相似度因此很低**：
  「暴雨蓝色」vs「暴雨篮色」只有 2/8 = **0.25**。拿 0.3 当门槛，最常见的
  中文错字（4 字词错一个）会全部漏掉。
- 但门槛降到 0.25 又会放进误报：「中国人民」与「中国银行」共享 `  中` ` 中国`，
  相似度 0.25，却并不是错字关系。

所以引入编辑距离 ≤ 1 作为第二条判据：它精确对应「打错 / 打多 / 打漏一个字」，
且「中国人民 / 中国银行」距离为 2、两条判据都不放行。相似度继续承担长词场景
与**排序**。两条判据缺一都会漏，故取或而非替换。

## 测试（48 项，`tests/test_search_suggest.py`）

- `trigram_similarity`：全同/全异/空串/差一字/短串；**补齐行为**与「4 字词只有 0.25」各一条
- `edit_distance_at_most_one`：替换、插入、删除、两次编辑、长度差 >1、尾部多字符
- 三源：hot 前缀、非前缀不算 hot、同 kind 按次数倒序；错字回到真实词、缺字、
  **相关但非错字被拒**、长度差过大被拒；标题前缀、超长标题、边界正好等于上限、已下架不参与
- 合并：hot 优先于 title（同词只出一次）、大小写去重、三源相对顺序、limit 截断
- 接口契约：空 q / 纯空格 / 不带 q、keyword 归一化、**不下发资讯字段**、
  **不写 search_logs**、免登录、limit 与 days 边界
- 正文召回：只出现在正文能召回、标题命中仍第一、摘要命中高于正文命中、
  已下架不召回、**fallback 不含正文**、通配符转义仍然生效

### 关于 `similarity()` 的测试脚手架

`_search_ranked` 是 PG 专属（依赖 `func.similarity`），而测试跑在 SQLite 上。
测试文件在 SQLite 连接上注册了一个同名的三元组函数，让这条路径**在 CI 里真被执行**。
它验证的是召回集合与层级顺序——这两件事只依赖权重间隔（100/10/1），
不依赖相似度的精确取值；绝对值由 `verify_search_ranking.py` 在真实 PG 上核对。

## 顺带修掉的债：P1-65 的模型/迁移漂移

`alembic check` 在本批回归里报出「`ix_reports_created_at` 未建」——
P1-65 给 `Report.created_at` 写了 `index=True`，但迁移 0031 没建它。
**这会让 CI 的「迁移漂移检查」步骤一直红。**

修法是去掉而不是补迁移：复核队列是 `status` 过滤 + `id` 倒序的 keyset
（`routers/admin/reports.py`），没有任何按 `created_at` 过滤/排序的查询——
一个没人用的索引只是给每次举报多加一次写放大。现在 `alembic check` 报
`No new upgrade operations detected`。

> 之前没被当成必做项。已记入项目记忆：本地回归必须含 `alembic check`（PG）。
