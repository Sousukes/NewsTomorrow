## 批次 P1-88：写路径差分回放 —— 首轮即抓到两处真漂移

## 背景

D8（P1-86）把差分契约扩到了需登录端点，但**只比 GET**——写路径
（POST/PATCH/DELETE）从未互相比对过。当时的理由是会污染开发库，
于是用 `DIFF_ALLOW_WRITES=1` 显式开关 + 「写入 → 比形状 → 撤销」的模式把它做出来。

## 一、首轮结果：两处真漂移，而且都藏在"数据为空"的盲区里

| 端点 | 差异 |
| --- | --- |
| `POST /me/favorites` | mock 的收藏项有 `content` / `hotScore` / `publishedAt`，缺 `cover` / `isTop` / `playCount` / `videoUrl`（**7 处**） |
| `POST /news/:id/comments` | mock 的新建评论缺 `isDeleted` / `replies` / `replyCount` |

两处的共同点：**对应的 GET 用例是绿的，但那是盲区**。
`GET /me/favorites` 两端返回的都是空列表 → "无比比数据"被静默放过；
评论列表走 `commentOut()`（它有 `replies`/`replyCount`），而**新建响应是另一条
内联构造的路径**，从没走过序列化函数。

也就是说：**不写一次数据，这两处形状差异在产品里永远看不到**——
离线演示收藏一条资讯、发一条评论，前端拿到的字段集与接真后端时不一致。

## 二、修法

1. **收藏/历史**：`payload()` 里的 `list` 改走 `publicNews(row)`
   （P1-83 加的公开序列化：剥 `content`/`hotScore`/`publishedAt`，
   补 `cover`/`videoUrl`/`playCount` 可空位与 `isTop` 布尔），
   不再直接吐内部 news 行。
2. **新建评论**：补 `isDeleted: false` / `replyCount: 0` / `replies: []`，
   与后端 `to_out` 对齐。注释里写清了"列表走 commentOut、这条不走"——
   正是这个分叉让差异活了下来。

## 三、设计要点

- **写操作默认不跑**：`DIFF_ALLOW_WRITES=1` 才启用。一个会自动写库的脚本
  不该是默认行为——打错 `API_REAL` 就是在往生产灌数据。
- **撤销放 `finally`**：比对失败也要收摊，不能把测试数据留在库里。
  本轮 4 条用例撤销零失败。
- **撤销用各自的创建响应**：两端生成的 id 规则不同
  （mock 是 `c_<时间戳>`），必须各用各的。
- **刻意不收的几类**（理由写进脚本，免得后人以为遗漏）：
  `POST /me/follows`（没有两端都合法的 sourceKey，打过去必然一边 422，
  那是数据不对等不是契约漂移）、`POST /news/{id}/likes`（mock 未实现）、
  `PUT /me/favorites` 合并语义（收益不抵复杂度）、admin 写端点（改运营配置，
  undo 语义各异）。

## 四、反向变异验证

把收藏项改回"内部行 + 一个多余键"：差分精确报出
`__MUTATION__ 仅 mock 有` 以及被拆掉的 `cover`/`isTop`/…，exit 1。

## 六、一个本机环境坑（值得记住）

`pkill -f "mock-server/server.mjs"` **在 Windows 上从未生效**：
进程命令行里是反斜杠路径，正斜杠模式匹配不到。结果新 mock 进程
`EADDRINUSE` 退出、旧 mock 继续服务——我第一次重跑时看到的
"评论修好了、收藏没修好"就是这个原因造成的**假象**。
正确做法：`netstat -ano | grep LISTENING` 取 PID 再 `taskkill //PID`，
或者干脆在同一次 Bash 调用内起服务 + 跑测试（后台进程跨调用会被回收）。
