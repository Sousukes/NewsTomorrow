## 批次 P1-2（2026-10-11）：评论删除（路线图第 5 项）
- **问题**：用户只能发评论、不能管理自己的评论。此前因 `Comment` 无 `user_id`
  无法判定归属，已在 P1-1 解决（0007）。
- **设计取舍：软删除而非物理删除**。评论可能已被他人点赞，抹掉会丢失互动记录；
  且后续审核/申诉需要留存原文。故 `is_deleted` 标记 + `deleted_at`，
  列表过滤已删除项，点赞接口拒绝已删除评论。
- **改动**：
  - `models.Comment` 增 `is_deleted`（NOT NULL 默认 false）/ `deleted_at`；迁移 `0008_comment_soft_delete`。
  - `DELETE /api/news/{news_id}/comments/{comment_id}`：401 未登录 / 404 不存在或已删 /
    403（40302）非作者 / 幂等重复删除返回成功 / 跨文章删除 404（防越权）。
  - 列表查询加 `is_deleted.is_(False)` 过滤；点赞接口对已删除项返回 404。
  - 输出增 `isDeleted` 字段。
- **前端**：`types.ts` 增 `isDeleted`；`api/comments.ts` 增 `deleteComment`；
  `stores/comments.ts` 增 `remove`（**乐观更新 + 失败回滚到原位置**）；
  `Comments.vue` 仅对 `mine` 的评论显示「删除」入口，带二次确认与失败提示。
- **测试**：后端 100 → **108 项**（`TestCommentDelete` 8 项：作者可删 / 未登录 401 /
  他人 403 且评论仍在 / 无归属不可删 / 幂等 / 删后不可点赞 / 不存在 404 / 跨文章 404）；
  前端 87 → **91 项**（新增 `stores/comments.spec.ts` 4 项）。
- **文档**：两个 README 测试清单与 store 说明同步。
