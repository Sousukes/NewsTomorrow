## 批次 P1-36（2026-10-17）：运维接口访问控制（C5）
backlog 规则生效后的第四批：偿还最上方的 C5。

**问题**：`/api/health` 与 `/api/metrics` 完全公开，前者返回**连接池状态**
（`size/checked_in/checked_out/overflow`）与热度重算状态，后者返回**Top20 路径分布**。
这些是内部可观测面：暴露给外部等于给攻击者一份「哪里被打、池是否打满」的实时地图。

**方案：单一 `OPS_TOKEN` + 环境相关的默认值**

| 配置 | 行为 |
| --- | --- |
| 设置 `OPS_TOKEN` | 必须携带 `Authorization: Bearer <token>` **或** `X-Ops-Token: <token>`；缺失/错误 → 403 / 40303 |
| 未设置 + `development` | **放行**（本地 / CI / 契约检查零改动） |
| 未设置 + `production` | **拒绝 403 / 40303**（fail-closed），启动时打印告警 |

- 两个头都接受：`Authorization: Bearer` 便于统一走现有鉴权通道，
  `X-Ops-Token` 让 Prometheus / 负载均衡探针不必伪造 Bearer 格式。
- 令牌比较用 `secrets.compare_digest`（定时安全，不按字符泄露前缀）。
- **刻意用 403 而非 401**：本项目里 401 代表「会话失效」，前端据此清登录态并跳登录页；
  运维接口与用户会话无关，返回 401 会误导客户端。用户 JWT 也不能当运维令牌（不同信任域）。
- `require_ops_access` 在**调用时**读 `config.OPS_TOKEN` / `config.IS_PRODUCTION`
  的模块属性（而非 `from .config import`），否则测试无法 monkeypatch 覆盖分支——
  与 `admin.is_admin` 读 `ADMIN_PHONES` 同一个理由。
- 顺带把 `deps._bearer_token()` 抽出来复用（原先 `_user_from_token` 里内联解析）。

**为什么 health 也要挡**：健康检查里带着池状态，与指标同属内部可观测面。
若探针不便带令牌，应由内网独占该路径，或另设不含内部状态的存活探针——README 已写明。

**测试**：新增 `tests/test_ops_auth.py`（**14 项**）：开发未配置放行、配置后缺凭据/错令牌
拒绝（403+40303）、`Bearer` 与 `X-Ops-Token` 两种头均放行、鉴权不影响 Prometheus 文本、
**用户 JWT 不能当运维令牌**、生产未配置 fail-closed（两接口各一组参数化）。
pytest 635 → **649 全绿**。

**契约影响**：开发环境行为与响应结构**完全不变**（契约检查无需改动）；
**生产环境未配置 `OPS_TOKEN` 时两个接口由 200 变 403**——这是刻意的 fail-closed，
已在 README / `.env.example` / 启动告警三处写明。
