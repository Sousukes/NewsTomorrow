## 批次 P1-41（2026-10-18）：修改密码 + 管理员代重置 + 强制改密（C4）
**问题**：全站没有任何改密通道——用户忘记密码只能无解，管理员也只能新建账号
（旧号的数据与身份就此悬空）。C4 的建议方向是「至少『管理员代重置 + 强制改密』，
或接入短信验证码」；后者需要外部服务与真实手机号（那是 backlog 的 C3，
且本项目目前没有任何可送达的凭证通道）。故本批落地**前者**：
把「验证身份」放在人身上，而不是假装系统能确认你是谁。

**后端**
- `PUT /api/auth/password`：自助改密。**两道证明**——`require_step_up`（令牌 + 密码）
  **与** `oldPassword`；单靠 step-up 不够（用户被诱导弹窗时输入的仍是他自己的密码，
  「旧密码错误」这道校验能挡住一部分）。改密后自增 `token_version` 作废全部旧凭证，
  同时**下发新的一对**——否则用户改完密被自己踢下线
- `POST /api/admin/users/{phone}/reset-password`：管理员代重置（管理员 + 二次校验）。
  临时密码由**服务端生成**（字符集剔除 `0/O`、`1/l/I` 等易混字符——它靠口头/手写
  传达，抄错率必须压到最低）；**不能重置自己**（40007，那是一条把自己踢下线的路）；
  用户不存在返回 **40400**（与公开接口同码，不能靠错误码区分手机号是否已注册）
- 迁移 **0028**：`users.must_change_password`（NOT NULL + `server_default false`，
  **不建索引**——它只参与「取到用户后读一个布尔」，没有按它过滤的查询）
- **强制改密（受限态）**：`must_change_password` 为真时，拦截写在**两个地方**——
  用户侧写操作用 `deps.require_password_current` 依赖（评论/收藏/历史/改昵称），
  管理端**全部**端点收敛在 `admin.require_admin` 一处判断（新增端点自动继承）。
  只拦写、不拦读：把账号整个锁死除了让人焦急，没有安全收益；
  真正要防的是「拿着临时密码对外产生影响」
- **审计不含明文**（`user.password.reset`）：审计表长期留存，写进明文等于给任何
  只读权限的人发一份密码清单（已加断言守住）

**前端**
- `/change-password` 一个页面承接两条入口：主动改密 + 被强制改密
- `mustChangePassword` 随登录下发并**落盘**（刷新页面后守卫仍有效），
  `router.beforeEach` 一处守卫（二十多个页面逐个判断必然漏）
- 改密成功后写入后端下发的新令牌对并清标志，顺带同步一次收藏/历史
  （受限期间它们的云端写入被拦过，本地数据还没并上去）
- 管理端「管理员管理」页做**手机号输入**式重置而非列表项——C4 的正主是普通用户，
  他们不在管理员白名单里；临时密码只显示一次，带复制按钮

**测试**：新增 `tests/test_password_change.py` **22 项**（两道证明 / 改密作废旧三类
凭证 / 受限态拦写不拦读 / 管理端进不去 / 代重置的权限与边界 / 临时密码字符集 /
审计无明文）；前端 store 4 项 + 路由守卫 3 项；契约新增 C4 断言。

**验证**：pytest 699 → **721 全绿**（退出码 0）；vitest 512 → **519**；
`verify` + `build` 通过；契约**双端双档全绿**——默认档 56 → **64**、
`CHECK_ADMIN=1` 262 → **277**。`alembic check` 无漂移。

**顺带补齐的 mock 缺口**：mock 此前**没有注册端点**（账号在登录时懒创建），
契约无法在双端跑同一条改密链路。补 `POST /auth/register`（昵称仍走 mock 既有的
校验链，不另造规则），并让 mock 的登录/二次校验改为比对**账号当前密码**，
否则代重置在 mock 里形同虚设。

**契约脚本的两个坑**：`const unknownReset = ''` 却在 catch 里赋值 →
`Assignment to constant variable`（默认档跑不到 CHECK_ADMIN 段才暴露）；
固定手机号注册第二次跑必撞 409，故改为按运行时间生成。
