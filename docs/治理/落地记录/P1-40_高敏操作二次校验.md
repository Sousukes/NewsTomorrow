## 批次 P1-40（2026-10-18）：高敏操作二次校验（C10）
**问题**：C10 由 P1-38 从 C1 拆出。会话令牌被偷（XSS / 共享设备 / 日志泄露）后，
攻击者拿到的不是「只读权限」，而是**与本人同等的能力**——包括把管理后台交出去
（`POST /api/admin/users`）、删掉 RSS 源、顶着别人的名字说话。这些操作的共同点是
**不可逆或影响全局**，理应要求「再证明一次你是本人」。

**机制**（`app/step_up.py`）：`POST /api/auth/step-up`（已登录 + 密码）换一张
5 分钟的 `typ=stepup` 令牌，受护端点以 `X-Step-Up-Token` 头校验。**刻意不新造
轮子，全部复用既有机制**：
- 复用 `login_guard` 的账号维度锁定（scope=`stepup`）——否则这个端点本身就是
  密码 oracle（猜对一次即可删源）；scope 隔离让「二次校验失败」不锁登录，
  但阈值/窗口共用一套配置；
- 复用 JWT 类型校验（与 C1 的 access/refresh 同源，三者互不通用）与
  `token_version` 吊销（登出即同时失效）；
- **body 里不收手机号**：那是把二次校验变成「可指定账号的登录端点」，
  猜密码的人顺带获得账号枚举。身份由 access 令牌给出。

**覆盖范围**（按「不可逆或影响全局」这条线划定，5 个端点）：
`PUT /me/nickname`、`POST/DELETE /api/admin/users`、`DELETE /api/admin/sources/{key}`、
`POST /api/admin/sources/reset`。
**未覆盖的及理由**：内容治理类（hide/restore/review、词库增删）**可逆且有审计日志**——
检测能力已具备，预防的边际收益低于「每个页面加弹窗」的成本。机制就绪后纳入一个
端点只是加一个 `Depends(require_step_up)`，这条边界写进了 README。

**前端**：`http.ts` 收到 40304 → 广播事件并挂起 → 全局密码对话框
（`StepUpDialog.vue`，挂 App 根部）→ 令牌存**内存**（5 分钟，刷新即失效，
不落 localStorage）→ 原请求带头重试一次。三处刻意：一次请求最多弹一次
（防弹窗循环）；`clearSession()` 一并清令牌；请求层不碰 UI（只广播与等待）。

**测试**：新增 `tests/test_step_up.py` **17 项**（端点本体 / 锁定与 scope 隔离 /
5 端点缺令牌全 40304 / 类型隔离 / 登出吊销 / **未授权者得 40301 而非 40304**）；
前端 `http.stepup.spec.ts` 7 项；昵称测试补 2 项（40304 与单用途）。

**验证**：pytest 680 → **699 全绿**（退出码 0）；vitest 505 → **512**；
`verify` + `build` 通过；契约**双端双档全绿**——默认档 56/56、
`CHECK_ADMIN=1` 全量档 **262/262**（含 3 项新增 C10 断言：缺令牌 40304、
换取 step-up 令牌、带令牌放行）。

**契约脚本的两处附带修复**（都是「默认档跑不到、被 C10 撞出来」的旧问题）：
1. `PUT /me/nickname` 的**形状校验**用例原本不带令牌 → 改造后先撞 40304，
   症状是「六态全部 42203」全变「需要二次校验」。改为**受护路径自动带头**
   （与前端 `http.ts` 同一套行为：客户端不该在每个调用点手工决定要不要二次校验），
   只在「故意验证 40304」的那条用例显式 `stepUp: false` 退出；
2. 审计段收尾的 `DELETE /admin/sources/__contract_audit` 同样漏了令牌，
   而它上面的 `catch { /* ignore */ }` 会把 40304 吞掉——症状是紧接着的创建
   报「该源标识已存在」，**与真正原因隔着两层**。补上令牌后连同开发库里
   的一次遗留临时源一并清理干净。

**测试改动的附带发现**：`test_invalid_phone_is_422` 原本不带 step-up 头，
改造后先撞 40304 而非 42200——说明**依赖先于 body 校验**。给该用例补上令牌后
仍断言 42200，顺带覆盖了「授权调用方的参数校验」这条路径。

**跑 `CHECK_ADMIN=1` 的前置**（踩过，写下来省下次重复）：后端须以
`ADMIN_PHONES=<当前手机号>` 启动；该档请求量远超默认阈值，还须抬高
`RATE_LIMIT_PER_MINUTE` / `LOGIN_RATE_LIMIT_PER_MINUTE`，否则会中途撞 42900
「请求过于频繁」。
