## 四个设计取舍

1. **未登录先给出口**：弹窗检测到未登录时只渲染「去登录」，不让用户选完理由再吃 401。
   把失败放在最后一步是最浪费用户操作的设计。
2. **不预选理由**：预选等于把第一个类目当成默认意图，误点一下就提交了一条自己没选的举报。
   未选时提交按钮禁用。
3. **不回显处置结果**：成功后只说「已提交，感谢反馈」，不展示 `autoHidden`/状态。
   回显等于把自动处置阈值告诉刷子，也给被举报人反向锁定举报人的线索（设计文档 §六）。
   `autoHidden` 仍由接口返回并归一化，留给日志与将来的举报进度查询。
4. **入口位置**：评论挂在评论操作行（回复旁边），资讯挂在导航「更多」。
   举报是低频负向操作，放进底部主操作区会抬高误触率，也稀释正向操作。

顺带修掉一个**定位上下文缺失**：`PhoneFrame` 没有 `position`，而弹窗遮罩用
`position: absolute` —— 实际会以视口为基准，遮罩铺满整个浏览器窗口、底部弹窗贴到页面底边
而不是手机底边（`StepUpDialog` 一直如此，只是没人从视觉上追究）。补一行 `position: relative` 即可。

## 两处刻意的不做

- **不做本地「已举报」状态**：服务端幂等语义是「重复举报只更新理由」，
  用户改主意换个理由正是真实意图，前端去重反而挡住了它。
- **mock 不模拟阈值自动处置**：真实处置需要 3 个不同账号，mock 无真实账号体系，
  假装会隐藏会让前端误以为链路已验。`autoHidden` 恒 `false` 是诚实边界。
