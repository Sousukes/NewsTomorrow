## 批次 P1-28（2026-10-18）：资讯正文落地（E1）
审查清单里唯一「产品可信度」级的问题：详情页展示的是前端写死的占位文案
（三段「据相关方面介绍……」），点进任何一条资讯看到的都是同一段假文本。
而服务侧其实早就拿到了正文——RSS 的 `content:encoded` 在 fetcher 里被读取，
**只用来提图，正文本身被丢弃**。

- **迁移 0025**：`news.content`（Text，**可空**）。可空即语义：NULL =
  「暂无正文」，详情接口据此如实返回 `null`；**不建索引**（只按 id 点查，
  无按正文检索需求——搜索走标题/摘要的 pg_trgm 方案）。存量行不回填：
  没有原始 XML 可回溯，回填只会造出假正文；下一轮抓取周期自然补上。
- **抓取（`fetcher.py`）**：`parse_feed` 优先取 RSS `content:encoded` /
  Atom `content`，**缺失回退 description**——很多源只给摘要字段，但那也是
  真实文本，比显示「暂无正文」更有信息量。`RawItem` 增 `content` 字段。
- **清洗（新增 `_clean_paragraphs`）**：块级结束标签与 `<br>` → 换行、
  去标签、解实体、**段内**压空白。与既有的 `_clean` 刻意分工——后者把整段
  压成一行，只适合摘要；正文几千字糊成一段没法读，段落必须活过清洗，
  且段落就是前端分段的依据（后端存 `\n`，前端切 `<p>`，不需要前端再猜标签）。
- **截断（`_truncate_paragraphs`）**：按**段落边界**截到 8000 字符——
  宁可少一段，不在句子中间砍断；单段本身就超限时退化为硬截断
  （几千字无换行的源确实存在），保证「一定有内容」且「一定不超限」。
- **入库（`ingest.py`）**：新增行写 `content`；增量刷新**非空才覆盖**
  （某轮抓到无正文的条目不该把已有正文抹掉——源抽风时尤其）；空正文落
  `NULL` 而非空串（「抓过但源没给」与「没抓过」可区分）。
- **下发（`news.py`）**：`to_out` **刻意不含** `content`——一页 20 条、
  每条几 KB 是纯浪费；只有 `GET /api/news/{id}` 详情单独返回，
  无正文为 `null`。**契约变更仅此一处**（新增字段，向后兼容）。
- **前端**：`NewsDetail.vue` 删掉 `body` 常量，按 `\n` 切段渲染；
  无正文显示「暂无正文」（弱化说明文案，**不伪装成内容**）。
  `NewsItem` / `normalizeNewsItem` / `validateNewsItem`（M8 运行时校验）
  同步增 `content`。mock 三处种子（`mockNews.ts` / `mock-server` /
  `app/seed.py`）补了真实正文，离线演示链路同样看得见。
- **mock 服务的对应口径**：列表/搜索路由经 `listOut` **剥离 content**
  （与后端 `to_out` 同口径），详情路由原样返回含 content 的条目。
  声明位置必须放在各 news 路由之前——这些路由是同一函数内顺序执行的
  if 块，声明在后会先被使用（TDZ），eslint 的 `no-useless-assignment`
  实际上帮我抓住了这个运行期才会炸的问题。
- **回归**：后端 pytest 594 → **611 全绿**（`test_units` +9 正文提取与清洗、
  `test_api` +3 下发口径、`test_migrations` +1 列断言、`test_sources` +4
  `TestUpsertContent` 落库语义）；前端 vitest 480 → **484**
