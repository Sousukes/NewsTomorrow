## 批次 P1-6（2026-10-11）：收藏 / 浏览历史云端同步（路线图第 4 项）
- **问题**：收藏与浏览历史**只存在前端 localStorage**——换设备、清缓存即丢失，
  也无法跨端一致；且无任何服务端数据支撑后续个性化。
- **后端**：
  - `models.py` 新增 `UserFavorite` / `UserHistory`，**复合主键 `(user_id, news_id)`**
    天然保证"同一用户同一资讯只有一条"（幂等基础）；分别按 `created_at` / `viewed_at` 建
    `(user_id, 时间列)` 索引。
  - 迁移 `0010_user_marks`：建表 + 索引 +（**仅 PostgreSQL**）`ON DELETE CASCADE` 外键。
    SQLite 默认不强制外键，故由 `prune_old_news` 在清理资讯时**显式删除**标记
    （与评论/消息同一策略，避免 SQLite 下残留孤儿标记）。
  - 新增 `routers/me.py`（`/api/me/*`，8 个端点，全部需登录、按 `user_id` 隔离）。
    - **契约**：所有写操作返回**完整最新集合** `{ ids, list }`——服务端即事实源，
      客户端"调用即可，结果即真相"；`list` 为完整资讯对象，使**新设备**无需额外请求
      即可渲染收藏/历史页。
    - **合并（PUT）为并集**：只增不删，避免客户端本地为空时误删云端；
      删除一律走显式 DELETE。并入条目的时间基准取 `max(now, 云端最大时间) + N 秒`，
      保证合并后顺序**完全确定**（先按传入顺序排并入项，再排云端原有项）。
    - **差异化的容错**：单条 `POST /favorites` 对不存在的资讯返回 404（显式用户操作），
      而 `POST /history` 静默忽略（详情页被动副作用，避免与时效清理竞态时抛无意义错误）。
- **前端**：
  - 新增 `api/me.ts`（8 个函数，导出 `MARKS_SYNC_SUPPORTED`——mock 模式下为 `false`，
    store 据此跳过同步）；`api/news.ts` 导出 `normalizeNewsItem` 供其复用；
    `stores/news.ts` 新增 `cacheMany()`，把云端返回的资讯写入详情缓存。
  - `stores/user.ts` 改造为**离线优先 + 云端同步**，且本地标记**按账号命名空间隔离**
    （`mingri-toutiao:marks:<anonymous|u<id>>`）：
    - 未登录时落在**匿名作用域**，登出不会丢失；
    - 各账号本地缓存互不可见，**不存在换账号串数据**；
    - 登录时把「匿名期数据 + 该账号缓存」**采纳**为该账号数据（匿名作用域随即清空），
      再与服务端做**并集合并**；登出仅切回匿名作用域，**账号数据保留在本地**，重新登录即恢复；
    - 写操作本地乐观生效 + 后台推送，推送失败**不回滚**（下次合并收敛）；
    - 作用域切换前先落盘旧作用域，避免 watcher 在切换后把旧数据写进新作用域；
    - 旧格式（标记内嵌在 `mingri-toutiao:user` 键）自动迁移到匿名作用域，**不丢用户已有数据**。
  - 并发保护：收藏/历史推送各带**序号守卫**，乱序响应不会覆盖新状态。
  - 性能小优化：`addHistory` 若目标已在列表首位则直接返回，省掉一次请求。
  - **修复一处真实缺陷**：空标记曾用共享常量 `{ favorites: [], history: [] }`，浅拷贝后各作用域
    拿到**同一个数组实例**，一处 `push` 会污染所有作用域（表现为"换作用域莫名多出别人的收藏"）。
    改为工厂函数 `emptyMarks()` 每次返回新数组。该问题由新增测试的作用域隔离用例暴露。
- **顺带修复的 mock 漂移**：`mock-server/server.mjs` 与真实契约存在两处**既有**不一致——
  评论列表仍返回裸数组（后端已是 `{ list, hasMore, nextCursor }`）、点赞非幂等（重复点赞会累加）。
  两者都会让 `contract-check` 在 mock 上失败，已一并修正。
