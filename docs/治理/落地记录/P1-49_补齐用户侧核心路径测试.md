## 为什么断言这几个点

不是「给每个函数写一行覆盖率」，而是挑**只在视图层存在、别处测不到**的规则：

- **「切频道不重置排序」**——store 层测不到，因为它是视图在两次调用之间
  传递排序参数的行为；
- **「后端错误文案原样透传」**——登录失败锁定（C2）上线后，错误多半是
  「账号已锁定，请 N 秒后重试」。视图若把它吞掉换成「登录失败」，
  用户只能反复重试，而那正是锁定策略最不希望发生的行为；
- **「未展开 = 最早 2 条预览」**——这条规则曾经放在 store 里又被挪回视图，
  钉一根钉子免得再漂。

## 踩到的三个坑

1. **mock 函数要写明参数类型**：`vi.fn(async () => undefined)` 会把
   `mock.calls` 推断成**空元组**，断言 `calls[0][0]` 时报
   `Source has 0 element(s) but target requires 2`；
2. **fixture 要按模板真正读的字段造**：模板用 `row.c.seed`（头像渐变种子）
   而不是我以为的 `name`，缺字段直接 `TypeError: Cannot read properties of
   undefined (reading 'length')`；
3. **`vi.clearAllMocks()` 会连 `calls` 一起清**：想先记住初始值再清桩，
   顺序反了就读不到 —— 这条与「先清再断言」的直觉相反，值得写下来。
