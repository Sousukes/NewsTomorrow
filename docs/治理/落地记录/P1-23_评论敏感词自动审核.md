## 批次 P1-23（2026-10-16）：评论敏感词自动审核（可配置词库 + 热更新 + 命中日志）
- **背景**：P1-22 给了运营「先隐藏再核实」的处置能力，但**处置仍然完全依赖人先看见**——
  广告、引流、博彩这类内容从发出到被看见之间是一段无人值守的窗口。本批补上写入侧的
  自动审核：**词库可配置维护、支持热更新、命中留痕供审计与统计**。
- **设计①：只堵唯一写入口**。`POST /api/news/{news_id}/comments` 是主评论与回复的
  **唯一写入路径**，检测放在**落库之前**。刻意**不做在读路径**——读多写少，
  读路径加检测是给每一次列表刷新付一次永远用不上的成本。前端校验只防误触，
  **服务端是唯一可信边界**。
- **设计②：三种动作，默认 mask 而非 block**。`block` = 拒绝提交、**不落库**（40005，
  提示**不回显命中词**——回显等于教人怎么改写绕过）；`mask` = 替换为 `*` 后发布并标
  `pending_review`（**默认**）；`allow` = 白名单，命中区间**被 allow 词完全包裹**才豁免。
  默认选 mask 是误杀成本考虑：block 会让人「说了半天没反应还不知道为什么」，
  mask 最多是内容变形，且留有复核入口找回。
- **设计③：归一化匹配（抗四类绕过）**。逐字符 `NFKC` → `casefold()` → 只保留 Unicode
  类别 `L*`（字母，含 CJK / 假名 / 谚文）与 `N*`（数字），空格 / 标点 / 零宽字符 /
  符号 / emoji 全部丢弃。归一化**保留原文下标映射**，因此脱敏改的是原文、
  长度取**词长**而非区间长度（`加 微 信` 命中 3 字词，脱敏只吃掉 3 个字而不是整段）。
  实测四类绕过变体（空格分隔 / 夹标点 / 全角空格 / 零宽字符）**全部拦截**。
  **不做重复字符压缩**——`好好` 压成 `好` 的误杀率远高于它拦下的量。
- **设计④：Aho-Corasick 自动机**。`O(n + 命中数)`，与词库规模无关——词库未来涨到
  两万条，单次评论检测仍是扫一遍正文。热路径只做一次建树 + 按指纹判断是否过期。
- **设计⑤：热更新双保险**。指纹取 `COUNT(*) + MAX(updated_at)`；本进程
  `engine.invalidate()` 清空 `_checked_at` **与 `_fingerprint`**（只清时间戳不清指纹，
  停用一条词后指纹变了却仍走缓存 = 热更新失效）；TTL **30s** 兜底集群内其他进程，
  另有 `POST /admin/words/reload` 手动触发。停用**立即生效**（契约有专门断言）。
- **设计⑥：误杀控制七条**。默认 mask；allow 豁免；**最短词长 2** 挡在入库（单字词
  误杀面太大）；**昵称命中一律降级为 mask**（昵称是历史数据，block 会让人发不出言）；
  block 不回显命中词；命中日志留原文片段（`SNIPPET_CONTEXT=30`，运营要能判断
  是不是误杀）；**停用优于删除**（删了就失去统计与复盘依据）。
- **数据结构（迁移 0023）**：`sensitive_words`（`word` 唯一索引 / `action` /
  `category` / `enabled` / `hit_count` / `created_by` / `created_at` / `updated_at`）、
  `sensitive_hits`（记**词本身**而非 `word_id`——词被删了日志仍可解释，`field` 区分
  `content|name`，block 时 `comment_id` 为 NULL，snippet 存原文）、`comments` 增
  `pending_review`（非空默认 false、**不建索引**）+ `reviewed_at`（**与 `hidden` 正交**：
  脱敏发布是「待复核」，运营隐藏是「已处置」，两件事不能挤进一个字段）。
- **配置**：`MODERATION_ENABLED` / `CHECK_NAME` / `CACHE_TTL_SECONDS`(30) /
  `MIN_WORD_LEN`(2) / `MASK_CHAR`(`*`) / `DEFAULT_ACTION`(mask) / `MAX_WORDS`(20000)。

- **踩坑（错误码不可跨场景复用）**：敏感词「太短」最初复用 **42201**，而 42201 已被
  「频道不存在」与「排序方式不支持」占用——**同一错误码承载三种语义，前端只能给一套
  文案**，用户会在选频道时看到「敏感词太短」。改为新增 **42202**，并同步后端代码、
  后端测试、mock（**只改敏感词那处，排序那处 42201 保持不动**）、契约脚本与探针。
  教训：**新增错误码前先查它是否已被别的场景占用**。
- **踩坑（mock 与后端都不提供词库单条详情）**：契约脚本原本按 REST 习惯调
  `GET /admin/words/:id` 拿「接口不存在」。列表 + 增删改已够用，**省一个端点少一处
  双端漂移**；改为从列表里查（`list.find(w => w.id === id)`）。
- **踩坑（契约临时词必须互不为子串）**：本段用了四个临时词 `契约拦截词` /
  `契约脱敏词` / `契约检查` / `契约检查子词`。若其中一个是另一个的子串
  （如 `契约检查` 与 `契约检查子词`），「停用 A 后应当放行」会因 B 仍命中而莫名变红。
  **白名单用例恰恰需要子串关系**，所以拦截词与脱敏词必须刻意设计成互不包含。
- **踩坑（跑契约脚本要用 node 而非 python）**：`.tmp-run-contract.py` 里若用
  `sys.executable` 去执行 `.mjs`，报 `SyntaxError: invalid character '（' (U+FF08)`
  ——看起来像脚本语法错，实则是 Python 在解析 JS。必须显式传 node 绝对路径。
