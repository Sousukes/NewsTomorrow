## 批次 P1-3（2026-10-11）：消息中心事件化（路线图第 2 项）
- **问题**：消息中心只有 4 条写死的系统通知，且是**全局广播**——
  所有用户看到同一份，"消息"名不副实。
- **关键前置**：真实互动消息必须**定向**，否则会出现"每个人都收到同一条别人的动态"。
  故先给消息加收件人维度：`messages.user_id`（**NULL = 广播**，非 NULL = 定向），
  迁移 `0009_message_recipient`；历史行保持 NULL，沿用既有广播语义，无需回填。
- **改动**：
  - 新增 `app/notify.py`：`notify_comment_on_article()`（通知同样评论过该资讯的其他用户）、
    `notify_comment_liked()`（通知评论作者）。
  - `routers/comments.py`：发表评论后触发通知；**仅在新增点赞**时通知作者。
    通知为旁路逻辑，`try/except` + `rollback`，失败不影响评论/点赞结果。
  - `routers/messages.py`：列表 / 未读数 / 全部已读均限定**可见范围**
    （定向给自己 OR 广播）；未读数的"已读"亦限定在可见集合内，避免计数偏小或为负。
- **行为约束（均有测试）**：触发者不通知自己；取消赞不打扰；反复点赞去重不刷屏；
  定向消息对他人不可见。
- **验证**：受控实验（全新用户）— 注册后 4/4 → 自己评论 4/4（不+1）→
  他人评论后 5/5（+1）→ 他人自己 4/4（不+1），首条消息为"你评论过的资讯有新动态"。
- **迁移**：`0009_message_recipient`。
- **测试**：后端 108 → **116 项**（`TestMessageEvents` 8 项）。前端无改动（91 项保持）。
