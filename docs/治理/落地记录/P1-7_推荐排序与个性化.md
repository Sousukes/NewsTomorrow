## 批次 P1-7（2026-10-13）：推荐排序与个性化
- **问题**：列表排序只有「置顶 → 发布时间倒序」，`recommend` 流因此只是"最新的全部内容"，
  缺热度与个性化语义；且 `comment_count` **从未被维护**（只在种子/入库时静态赋值），
  评论增删都不计数，详情页评论数与真实条数不符。
- **后端**：
  - 新增 `app/ranking.py`：热度分 `hot = (评论×3 + 收藏×2 + 播放÷1000) × 时间衰减 × 100`，
    衰减 `1/(1+小时数/48)`（48h 半衰）。**时间可注入**，测试不依赖真实时钟。
  - **热度分落库**（`news.hot_score`，迁移 `0011_news_hot_score` + `ix_news_hot` 索引）：
    查询时计算需 JOIN 聚合收藏数，既慢又无法建索引，且游标分页要求排序键是稳定标量。
  - `sort` 三模式：`latest`（时间）/ `hot`（热度）/ `for-you`（热度 + 频道偏好加分）。
    偏好由 `UserFavorite`（权重 3）与 `UserHistory`（权重 1）统计频道分布归一化而来，
    加分上限 300（约"10 条评论"量级）——**偏好只提升次序，压不过真正热门的内容**。
  - **用加分而非"配额"**：配额式"偏好频道多给几条"要在应用层组装候选，
    与 keyset 游标分页不兼容；加分保持排序键为单一标量，游标语义不变。
  - **游标版本化**：v2 为 `[2, sort, is_top, key, id]`——若不携带 sort，`hot` 游标会被当成
    `published_at` 解析而错位。v1（3 元素）仍按 `latest` 兼容解析，老客户端翻页不失效。
  - 更新时机：互动发生即 `bump_hot_score()` 增量重算；定时任务抓取后 `recompute_hot_scores()`
    全量重算（刷新时间衰减）。热度是派生数据，失败仅记 warning，**不影响主流程**。
- **顺带修复的真实缺陷**：`comment_count` 此前从未随评论增删变化。现创建 +1、删除 -1（下限 0），
  使详情页计数与热度分的评论维度都可信。
- **权重调整（实测驱动）**：`PLAY_DIVISOR` 初版取 100，实测出现**零评论的高播放视频霸榜**
  （10 万播放 ÷100 = 1000 压过 512 条评论的 1536）。改为 1000 后热榜由讨论度主导、排序单调。
- **前端**：新增 `constants/sort.ts`（与后端、mock 三方一致的单一来源）、`api/news.ts` 透传
  `sort` 且非法值归一化、`stores/news.ts` 记住 `currentSort` 供 `loadMore` 沿用
  （**换排序会让服务端游标失效**）、`HomeFeed.vue` 频道栏下新增排序切换 + 个性化说明。
- **测试**：后端 142 → **173 项**（新建 `tests/test_ranking.py` 29 项）；
  前端 126 → **138 项**（`constants/sort` 6 + `api/news` 3 + `stores/news` 3）；
  契约 20 → **25 项**（新增排序三模式与非法 `sort` 422），**真实后端与 mock 后端均 25/25**。
