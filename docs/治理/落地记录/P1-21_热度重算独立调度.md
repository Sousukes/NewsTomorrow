## 批次 P1-21（2026-10-15）：热度重算独立调度（抓取停了，衰减不能停）
- **背景**：热度分（`news.hot_score`）的时间衰减此前靠抓取 cron 「顺带」全量重算
  （`_run_once` 抓完执行 `recompute_hot_scores()`）。三个后果：
  ① `FEED_CRON_ENABLED=false` 时**衰减永不推进**——hot / for-you 排序冻结，
  而演示 / 开发 / 只读副本常这么配；② 重算节奏被抓取周期绑定（抓取 30 分钟一轮，
  衰减也只剩 30 分钟粒度）；③ `run_ingest` 抛异常时重算被连带跳过。
  用户在上批收尾时选定本批（另一个候选「评论治理」顺延为 P1-22）。
- **设计①：独立 cron，不是并行保留**。`scheduler.py` 拆出 `_hot_loop` / `_hot_job` /
  `_run_hot_once`，`_run_once`（抓取）里**移除**热度调用——寄生关系整个拆掉，
  而不是「再起一个重复的」。独立开关 `HOT_CRON_ENABLED`（默认 true）、
  独立周期 `HOT_CRON_INTERVAL_MINUTES`（默认 15）。
- **设计②：第二把 advisory lock，键必须不同**。抓取锁 `0x746F7574`（"tout"）、
  热度锁 `0x686F74`（"hot"）。`_try_lock/_release_lock` 泛化出 `key` 参数。
  键若相同，热度任务会被另一实例的抓取锁**整轮跳过**——那等于把拆开的又粘回去，
  且这种退化在单机测试里永远看不见（SQLite 下都视为获取），用
  「两把锁键不同」的断言焊死。
- **设计③：增量重算 + 锚点列**（迁移 **0021**：`news.hot_score_at`，String(30)，
  可空、无 server_default、**不建索引**）。`only_stale=True` 只刷锚点为 NULL
  （迁移前存量首轮补锚点）或早于 `now - HOT_STALE_MINUTES`（默认 60）的行。
  staleness 窗口（60）> 周期（15）⇒ **每行每窗口最多重写一次**；无变动也全表重写
  是纯写入放大（dead tuple / WAL），而半衰期 48h 下 60 分钟约 2% 衰减，排序无感。
  不建索引的理由同 0020 的 `hidden`：表有 prune 上限，每轮扫全表找过期行足够便宜。
- **设计④：锚点即刷新**。互动 `bump_hot_score` 与全量重算都写 `hot_score_at`——
  刚算过的行不会被下轮增量重复扫到。`me.py` 批量合并收藏仍走**全量**重算
  （登录时稀有事件，行为不变）。
- **设计⑤：字符串锚点而非 DateTime**。与 `now_str()` 同格式（naive、秒精度）的
  ISO 串**字典序即时间序**，staleness 判定免一次类型转换，也规避 SQLite/PG
  时区语义差异（tz-aware 输入先经 `_to_naive_utc` 归一）。
- **设计⑥：health 暴露 + 失败不杀循环**。`/api/health` 增 `hotRecompute`
  （`enabled`/`lastAt`/`lastCount`/`lastError`，进程内、重启清零）——
  **抓取关停时这是热度任务仍活着的唯一信号**。热度是派生数据：单轮异常只落
  `last_error` 并 warning，调度循环继续。
- **测试**：后端 419 → **432 项**。新建 `tests/test_scheduler.py` **6 项**：
  核心回归「抓取关停 → 热度任务照建照跑、抓取一次不执行」、抓取单轮不再顺带
  重算热度（结构性解耦，打桩 `recompute_hot_scores` 断言零调用）、
  每轮异常都不杀循环（0.001 分钟周期跑 1 秒 ≥3 轮）、`_hot_job` 失败只落
  `lastError` 恢复即清零、`/api/health.hotRecompute` 四键形状、
  `hot_status()` 返回副本；`test_ranking.py` +5（`TestIncrementalRecompute`：
  增量只扫过期行且**未过期行的分数与锚点都不动**、窗口内行跳过、全量模式忽略
  staleness、同一 now 下增量分数与全量一致、bump 刷新锚点）；
  `test_multi_instance.py` 3 → 4（双锁键不同，并适配 `_try_lock(db, key)` 新签名）；
  `test_migrations.py` 19 → 20（0021 守卫：列存在、可空、无索引）。
- **踩坑（实现漏网语法错误）**：`config.py` 的 `HOT_STALE_MINUTES` 行**少写一个
  右括号**，直到 pytest 收集期 `import app.config` 才以 SyntaxError 暴露——
  前面几轮改动没有任何一次真正 import 过应用。教训：**改完配置/代码先
  `python -c "import main"` 冒烟**，别把首次编译留到测试收集（本期已先冒烟再跑测试）。
- **踩坑（测试环境竞态，提前拆除）**：`HOT_CRON_ENABLED` 默认 true，而 conftest 只关了
  抓取 cron——TestClient 的 lifespan 会启动热度任务，其「启动即执行」的首轮与测试
  主线程**并发**重算，把用例显式设定的 `hot_score` 冲掉，排序断言随机失败（race，
  极难复现）。修复：conftest 同步 `HOT_CRON_ENABLED=false`（调度器自身行为在
  `test_scheduler.py` 里用桩隔离验证，不依赖该开关）。
