## 批次 P1-16（2026-10-15）：抓取链路治理（并发化 + 礼貌抓取 + 超时告警）
- **背景**：上一批收尾时列出的三个候选（源抓取超时告警、源级限流与礼貌抓取、单源抓取并发化）
  经评估后**合并为一批**——它们耦合在同一段 `collect()` 里，且「并发化」与「礼貌抓取」
  存在硬性先后关系：源变多后串行会让一轮耗时线性增长，但**没有按源约束的并行化等于把压力
  转嫁给对方站点**（也可能被封）。用户确认「三项一起做」，robots **遵守但可逐源关闭**。
- **并发但不失序（关键设计）**：`collect()` 改两阶段——先线程池**并发抓取**，再按权重降序
  **串行合并**。「同 id 保留先到的一条」是先到先得的语义，若合并也并发，"
  多源转载同一稿件时权重高者先入库"这条规则就失效了。`stats` 同理按权重序而非完成序，
  避免健康回写/审计顺序随网络快慢漂移。
- **按 host 分组**：同站点源归一组、**组内串行 + 间隙**，组间才并发——并发的意义是省等待，
  不是把同一站点打 N 遍。测试用**并发峰值**断言（同站恒为 1、异站为 2）而非计时。
- **robots.txt（逐源可关）**：取不到就放行（404/不可达/不认识的格式——没有声明不等于禁止）；
  **按 host 缓存**（TTL 走 `FEED_ROBOTS_TTL_HOURS`）；**被禁记为异常**（`last_status=error`
  + 原因，源管理页可见，不静默抓取）；逐源开关应对"robots 写得过严却公开提供 RSS"的源。
  关闭遵守是**主动破例**，列表上以琥珀色「忽略 robots」标记持续可见。
- **单源最小抓取间隔**：定时任务与手动触发叠加时不重复打同一个源；
  **按礼仪跳过的源本轮不刷新健康状态**——刷新会让"多久没成功"永远归零（`stats.skipped`）。
- **健康告警（新模式）**：健康字段此前只落库，源悄悄烂掉没人被通知。每轮抓取收尾检查：
  判定 = `last_status=error` 或 `last_fetched_at` 为空/超时（只看**启用中**的源）；
  收件人 = 管理能力（env ∪ 库白名单）解析成**已注册**用户投递消息中心；
  节流锚点 `last_alerted_at` **落库**（多实例共享窗口、重启不失效）；
  **无收件人不推进锚点**（没通知到人就不该占窗口）；告警是旁路逻辑，失败由调用方吞掉。
- **指标**：`GET /api/metrics` 新增 `toutiao_sources_unhealthy`；查询失败返回 `-1`
  （用不可能的计数表达"未知"，而不是假装健康）。
- **前端**：源表单加「遵守 robots.txt」开关（默认勾选）、列表以琥珀色标记展示破例的源、
  审计页把该字段渲染成「遵守→忽略」而非 true→false；`api/admin.ts` 的 `toSource()`
  **缺字段按更保守的一方兜底为 `true`**；mock 后端 `sourceOut`/POST/PATCH 同步该字段。
- **踩坑（真 bug，本批最有价值的一条）**：`respectRobots` 是项目里**第一个多词入参字段**
  （响应侧早有 `lastStatus` 等驼峰，但入参此前全是单词）。初版把它写成蛇形
  `respect_robots`，而 pydantic 默认 `extra='ignore'` —— **前端发来的 `respectRobots`
  被静默丢弃**。后果是「开关看得见、点得动、永远不生效」：
  新增时关掉无效（落库仍是默认 `true`）、PATCH 也永不生效。
  最阴的是**前后端各自的单测都不会失败**——前端断言的是自己发出去的 body（确实带
  `respectRobots`），后端没有覆盖该字段的 API 用例，缝合处的缝两边都照不到。
  1. 最小复现（可直接对 pydantic 跑）：`class M(BaseModel): respect_robots: bool = True`，
     `M.model_validate({'respectRobots': False}).respect_robots` → `True`（被丢弃）。
  2. 修法：跟齐既有惯例，入参多词字段直接用**驼峰**（`SourceIn.respectRobots` /
     `SourceUpdateIn.respectRobots`），路由侧显式映射 `COLUMN_OF = {"respectRobots": "respect_robots"}`。
  3. 补回归：`test_respect_robots_round_trips_through_api`（**从 API 打到数据库**，
     覆盖「不传即默认遵守 / 新增显式关闭 / PATCH 关→开」）+
     `test_health_dict_carries_respect_robots_for_fetcher`（DB → 抓取入参那一跳）。
  **教训：新增任何多词字段，必须有一条「HTTP 入参 → 数据库」的端到端断言；
    只测前端发出的 body、或只测内部函数，都拦不住字段名不对齐。**
- **踩坑（测试预期写反了）**：①「无收件人是否推进节流锚点」我最初按"推进"写断言，
  与实现（提前返回、不推进）不符——想清楚后**实现是对的**（没通知到人就不该占用窗口，
  否则管理员一注册要白等 6 小时），改的是测试与注释；②并发峰值断言最初把 `sleep` 放在
  计数**之前**，两线程并没真正重叠在计数窗口内 → 改为只延长**响应**耗时
  （计数仍在 `get()` 里加减），断言才有意义。
