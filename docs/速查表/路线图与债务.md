| **P1-36（C5）** | **运维接口访问控制** | `/api/health` 与 `/api/metrics` 完全公开：前者返回**连接池状态**（`size/checked_in/checked_out/overflow`）与热度重算状态，后者返回 **Top20 路径分布**——等于给外部一份「哪里被打、池是否打满」的实时地图。方案：单一 `OPS_TOKEN`，可用 `Authorization: Bearer` 或 `X-Ops-Token` 两种头（后者便于 Prometheus / 探针）。**未设置时按环境分流**：`development` 放行（本地 / CI / 契约检查零改动）、`production` **拒绝 403+40303**（fail-closed，启动打告警）。令牌比较用 `secrets.compare_digest`。**刻意用 403 而非 401**：401 在本项目代表「会话失效」，前端会清登录态跳登录页，运维接口与用户会话无关；用户 JWT 也不能当运维令牌。`require_ops_access` 调用时读 `config.OPS_TOKEN` / `config.IS_PRODUCTION` 模块属性（否则测试无法 monkeypatch）。顺带抽出 `deps._bearer_token()` 复用。**开发环境契约完全不变；生产未配置令牌时两接口 200 → 403（刻意 fail-closed，README/.env.example/启动告警三处已写明）**；后端测试 635 → **649**（新增 `tests/test_ops_auth.py` 14 项） |
| **P1-37（C7）** | **命中日志留存治理** | `sensitive_hits` / `nickname_hits` 的 `snippet` 存的是**用户原文**（脱敏不可逆，是误杀复盘与申诉的唯一证据），但**没有任何保留期限**——日志只增不减，用户原话被无限期保存，属数据最小化原则下的合规风险。方案：① `HIT_LOG_KEEP_DAYS` 默认 **90 天**（`0` = 不清理，仅取证期临时用）；② **不设保底条数**（与 `prune_old_news` 的 `keep_min` 刻意不同：保留期就是它的全部价值，保底反而留下一批最旧的用户原话）；③ **双触发清理**——每次启动扫一遍（`lifespan`，**不依赖 cron**：`FEED_CRON_ENABLED=false` 时抓取 cron 不跑，合规清理不能跟着停）+ 抓取 cron 每轮顺带；④ 实现 `app/hit_logs.py::prune_hit_logs()` 按 `created_at < now - keep_days` 删两表；⑤ **可见范围**仅两个 admin 命中日志端点（受 C6 router 级鉴权保护），公开接口不返回 `snippet`。**累计计数不回退**：`nickname_words.hit_count` 是聚合值（发现高频词/误杀大户），与"还剩多少原文证据"是两个问题。**无契约 / 迁移变更**（不改表结构、不改接口形状）；后端测试 649 → **656**（新增 `tests/test_hit_logs.py` 7 项） |
| **P1-38（C1）** | **令牌双轨 access / refresh** | 全站只有一张 7 天令牌（`JWT_EXPIRE_MINUTES=10080`）且存 localStorage：真正的风险不是「7 天」这个数字，而是**只有一张令牌、没有任何缩短手段**——泄露（XSS / 日志 / 共享设备）后攻击窗口就是整整 7 天。修复：① `create_token` 增 `token_type`（`access`/`refresh`）并写 `typ`，`decode_token_full(expect_type=...)` **按类型校验**（refresh 若能被业务接口接受，攻击者拿到它就能当永久 access 用，「短 access」形同虚设）；② 有效期**按类型取默认**——access 30 分钟、refresh 7 天（兼容旧变量 `JWT_EXPIRE_MINUTES`，其历史语义就是那张长令牌，老部署升级后 refresh 时长不变）；③ 登录/注册/续期同时下发 `token` + `refreshToken` + `expiresIn`，**字段名与错误码对旧客户端零破坏**（新增两项刻意可选）；④ `/auth/refresh` 优先用 body 的 `refreshToken` 换发，缺省回退到 `Authorization` 的 access 滑动续期（兼容旧客户端 / 契约脚本），但 **refresh 无效时不回退**（否则过期长令牌能无限滑下去）；⑤ 登出自增 `token_version` → 两类令牌同时失效。前端：三键**同写同清**（`token`/`refreshToken`/到期时刻，只清 access 会留下可用的长令牌）、到期前 60 秒**主动续期**且并发**单飞**、401 先续期**重试一次**再兜底（限制「一次请求最多续一次」，否则「续期成功但仍 401」会死循环）。**无迁移 / 无破坏性契约变更**；后端 656 → **673**（新增 `tests/test_auth_tokens.py` 17 项），前端 488 → **496**，契约双端 53/53（各 +5 项）。**本批由测试抓出 1 个真 bug**：`create_token(type=refresh)` 不传有效期时退回 access 的 30 分钟 |
| **P1-39（C9）** | **内容安全策略 CSP** | 令牌存 `localStorage`，一次 XSS 即等于令牌泄露（access 已收窄到 30 分钟，但「窗口短」不等于「不发生」）。**分两半落**：后端不托管 SPA（`main.py` 无 StaticFiles，仓库也无部署编排），故 ① SPA 侧策略由 **构建期** `vite.config.ts` 插件注入 `index.html` 的 `<meta http-equiv>`（静态托管必定生效，不依赖基础设施改造），`src/security/csp.ts::buildCsp({dev,apiBase,transport})` 生成；② 后端侧 `app/security_headers.py` 给 `/api/*` 发 `default-src 'none'; frame-ancestors 'none'; base-uri 'none'`（JSON 无文档上下文 → 任何资源加载都是异常），另加 nosniff / Referrer-Policy / X-Frame-Options。要点：`script-src 'self'` **不放行** unsafe-inline/unsafe-eval（策略核心价值）；`style-src` 必须带 `'unsafe-inline'`（Vue 作用域样式 + 组件内联 style 属性）；`connect-src` 由 `VITE_API_BASE` 推导（写死会要么生产连不上后端、要么开发挡掉 API），开发态额外放行 ws 与 localhost；**`frame-ancestors` 只在 `transport:'header'` 下发**（它在 `<meta>` 里被规范忽略，留在 meta 版会误导）；只给 `/api/*` 上 CSP（`/docs` 依赖 CDN+内联脚本且仅 development 存在）；中间件**注册在限流之后**（后注册=最外层，429 也带上），并用源码顺序断言守住。**诚实边界**：`img-src`/`media-src` 必须放行 `https:`，挡不住 `<img src=https://evil/x>` 外泄型载荷，收紧要等 B4 图片代理 |
