#### P1-18 详情：失败分级与熔断
**为什么先分级**：404 和超时此前被同等重试、同等计数、同等告警，
于是「等它自己恢复」与「去改配置」这两件不同的事都被含糊成了"再试一次"。

| 项 | 规则 |
| --- | --- |
| `transient` 可重试 | 超时 / 连接重置 / 5xx / **429**（429 只是限流，等一会儿就能过） |
| `permanent` 永久 | 其余 4xx（401/403/404…）/ robots 拒绝 / **解析成功但 0 条** |
| 重试 | 仅 `transient` 消耗 `FEED_RETRY_TRANSIENT`（默认 2 次）+ 指数退避 `FEED_RETRY_BACKOFF`（0.6s） |
| 计数 | `consecutive_failures` **落库**（进程内计数多实例不共享、重启即清零），成功一次归零 |
| 熔断 | 达 `FEED_CIRCUIT_THRESHOLD`（默认 5）写 `next_retry_at`，冷却 `FEED_CIRCUIT_COOLDOWN_MINUTES`（30 分）内**整轮跳过该源且不刷新健康状态**，到期自动恢复 |
| 自动禁用 | `FEED_AUTO_DISABLE_PERMANENT`（**默认 0 = 从不**）；开启后每次触发写审计 `source.auto_disable`（`actor_phone="system"`） |

> `kind` 必须作为**结构化数据**穿过线程池：异常被 `str(e)` 拍平后没法再分类，
> 元组返回会在半路丢掉。所以它挂在 `FetchError.kind` 上，一路存进 `failure_kind`。

**接口字段**（`GET /api/admin/sources` 每行）：

| 字段 | 类型 | 前端兜底 |
| --- | --- | --- |
| `consecutiveFailures` | int | 缺失/非法 → `0` |
| `failureKind` | `"permanent"` \| `"transient"` \| `null` | 不认识的取值 → `null`（**不猜性质**） |
| `nextRetryAt` | ISO 串 \| `null` | 空串/非法 → `null` |

**审计新动作**：`source.auto_disable` → 「自动禁用源」；`detail` 为
`{ snapshot: { name, consecutive_failures, last_error } }`，
`actorPhone === "system"` 在页面上渲染为「系统自动执行」（不是某个账号）。
| 上限保护 | 摘要强制 `[:300]`，对齐 `messages.summary` 列宽 |

**为什么按原因分组**：分组本身携带了「这是不是系统性问题」——`超时未抓取 8 条`
已经指向该查定时任务或网络，不需要再写一句「建议排查网络」（那句大概率被省略号吃掉）。

**前端影响面**

| 项 | 变化 | 涉及文件 |
| --- | --- | --- |
| 类型 | `RssSourceItem.respectRobots: boolean`；`SourceInput.respectRobots?` | `types.ts` |
| 接口层 | `toSource()` 透出该字段，**缺字段按更保守的一方兜底为 `true`** | `api/admin.ts` |
| 页面 | 源表单加「遵守 robots.txt」开关（默认勾选）；列表对关闭该开关的源显示琥珀色「忽略 robots」标记 | `views/AdminSources.vue` |
| 审计 | 字段标签「遵守 robots」，取值渲染为「遵守→忽略」（而非 true→false） | `views/AdminAudit.vue` |
| mock | `sourceOut` / POST / PATCH 同步该字段 | `mock-server/server.mjs` |

> ⚠️ **入参多词字段走驼峰**（`respectRobots`）：后端 `SourceIn.respectRobots` /
> `SourceUpdateIn.respectRobots`，路由用 `COLUMN_OF = {"respectRobots": "respect_robots"}` 映射到列。

> 且前后端各自的单测都不会失败。回归防线：`test_respect_robots_round_trips_through_api`
> （HTTP 入参 → 数据库）。
