#### P1-12 详情：二级评论 + 点赞关系表化
**结构契约**：主评论 `rootId = null`；回复 `rootId = 所属主评论 id`，**回复的回复拍平到同一
root**（`root = parent.rootId || parent.id`），`parentId` 仅用于展示「回复 @谁」。

**接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/news/:id/comments` | **只返回主评论**（`root_id IS NULL`），每条附 `replyCount` 与最早 2 条回复预览；时间倒序，游标分页 |
| GET | `/api/news/:id/comments/:cid/replies` | 某主评论的回复列表，时间**正序**（讨论先后），游标分页；root 已软删除 → 返回空列表 |
| POST | `/api/news/:id/comments` | 带 `parentId` 即为回复；目标不存在/跨文章/已删 → 40003；回复只通知被回复者（不广播） |
| PATCH | `/api/news/:id/comments/:cid` | 点赞/取消（`comment_likes` 关系表，复合主键防重，幂等） |

**评论对象新增字段**（均为可选，旧数据按主评论形态兜底）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `parentId` | `string \| null` | 被回复的评论 id；主评论为 null |
| `rootId` | `string \| null` | 所属主评论 id；主评论自身为 null |
| `replyCount` | `number` | 主评论下的回复条数（已删不计；回复项恒 0，不嵌套） |
| `replies` | `Comment[]` | 主评论附带的**最早 2 条预览**；完整列表走 replies 接口懒加载 |
| `replyToName` / `replyToUserId` | `string \| null` / `number \| null` | 回复场景的被回复者（「回复 @谁」） |
