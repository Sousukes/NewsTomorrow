#### P1-30 详情：登录失败锁定（C2）
**互补关系**：IP 限流是「来的人别太猛」，账号锁定是「这个账号别被万人盯」。
分布式爆破的每个 IP 都是首次访问，IP 维度干干净净——只有账号维度能看见。

**判定流程**（`login` 端点）

```
格式校验(40001) → 锁定预检(42902, blocked 窥探不计次) → 查库+验密
                                                      ├ 失败 → 记一次(allow) + 40101
                                                      └ 成功 → 清零(reset) + token
```

**四个防绕过设计**

| 攻击面 | 设计 |
| --- | --- |
| 锁定期间继续刷 → 锁定期被无限续期 | 预检用 `blocked()` 只窥探；锁定后请求不碰计数器 |
| 只锁已存在账号 → 「同号有时 429 有时 401」枚举 oracle | 锁定先于用户查询，不存在账号同样计数 |
| 5 次手滑 + 1 次成功 + 1 次手滑 = 误锁 | 成功登录 `reset()` 清零，计数只反映连续失败 |
| 爆破期间每次请求都算 pbkdf2 → CPU 被拖 | 锁定判定在验密之前，已锁请求成本趋零 |

**误伤面（固有取舍，写进文档）**：持正确密码的用户可能被攻击者故意锁 15 分钟。
所以默认阈值 5 次（真人手滑空间）不宜再低；窗口 15 分钟是「等一会」而非「找人工」。
