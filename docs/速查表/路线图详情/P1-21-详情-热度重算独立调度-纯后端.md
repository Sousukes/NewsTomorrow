#### P1-21 详情：热度重算独立调度（纯后端）
**补的缺口**：热度分的时间衰减靠抓取 cron「顺带」全量重算。抓取被关停时
（演示/开发/只读副本常这么配）衰减永不推进，hot / for-you 排序直接冻结；
重算节奏也被抓取周期绑定；`run_ingest` 抛异常时重算被连带跳过。

| 设计 | 规则 |
| --- | --- |
| 独立 cron | `HOT_CRON_ENABLED`（默认 true）/ `HOT_CRON_INTERVAL_MINUTES`（默认 15）；`_run_once`（抓取）里**移除**热度调用，两条 cron 互不依赖 |
| 双锁分键 | 抓取锁 `0x746F7574`（"tout"）/ 热度锁 `0x686F74`（"hot"）——键若相同，热度任务会被另一实例的抓取锁整轮跳过，等于把拆开的又粘回去 |
| 增量重算 | `news.hot_score_at`（迁移 **0021**，String(30) 可空、**不建索引**）：只刷 NULL（存量首轮补锚点）或早于 `now - HOT_STALE_MINUTES`（默认 60）的行 |
| 窗口 > 周期 | 60 > 15 ⇒ 每行每窗口最多重写一次；无变动也全表重写是纯写入放大，而半衰期 48h 下 60 分钟约 2% 衰减，排序无感 |
| 锚点即刷新 | 互动 `bump_hot_score` 与全量重算都写 `hot_score_at`——刚算过的行不会被下轮增量重复扫到 |
| 字符串锚点 | 与 `now_str()` 同格式（naive、秒精度）ISO 串，**字典序即时间序**，免类型转换、规避时区语义差异 |
| health 暴露 | `/api/health.hotRecompute` = `{enabled, lastAt, lastCount, lastError}`（进程内，重启清零）；抓取关停时这是热度任务活着的唯一信号 |
| 失败不杀循环 | 热度是派生数据：单轮异常只落 `last_error` 并 warning，调度循环继续 |

**`recompute_hot_scores(db, now, *, only_stale, stale_minutes)`**

| 调用方 | 模式 | 说明 |
| --- | --- | --- |
| 热度 cron（`_run_hot_once`） | `only_stale=True, stale_minutes=HOT_STALE_MINUTES` | 只推进时间衰减 |
| `me.py` 批量合并收藏 | 全量（默认） | 登录时稀有事件，行为不变 |
| 测试 / 手动脚本 | 任意 | `now` 可注入 |

**测试规模**：后端 pytest 419 → **432 项**（+13：`test_scheduler.py` 6 项新建、
`test_ranking.py` +5 增量重算、`test_multi_instance.py` +1 双锁键、
`test_migrations.py` +1 锚点列守卫）；前端 Vitest **321 项不变**（无前端变动）；
契约脚本 **114 项不变**（无接口契约变动）。

> ⚠️ **conftest 必须同时关停两条 cron**：`HOT_CRON_ENABLED=false`。
> 否则 TestClient 的 lifespan 会启动热度任务，其「启动即执行」的首轮与测试
> 主线程并发重算，把用例显式设定的 `hot_score` 冲掉——排序断言随机失败，
> 且是 race 而非逻辑错，极难复现。
