#### P1-37 详情：命中日志留存治理（C7）
**问题**：`sensitive_hits` / `nickname_hits` 的 `snippet` 是**用户原文**，
但日志只增不减 —— 用户原话被无限期保存（数据最小化原则下的合规风险）。

**规则**

| 项 | 取值 |
| --- | --- |
| 保留期 | `HIT_LOG_KEEP_DAYS`，默认 **90 天**；`0` = 不清理（仅取证期临时用） |
| 保底条数 | **无**（保留期就是它的全部价值；保底会留下最旧的用户原话） |
| 清理时机 | ① **每次启动**（`lifespan`，不依赖 cron）；② 抓取 cron 每轮顺带 |
| 可见范围 | 仅 `GET /api/admin/moderation/hits`、`GET /api/admin/nickname-hits`（C6 router 级鉴权）；公开接口不返回 `snippet` |

**为什么启动也要清**：合规要求"过期即删"，不能因为 `FEED_CRON_ENABLED=false`
（抓取 cron 不跑）就停止删除。启动清理失败只告警、不阻断启动。

**累计计数不回退**：`nickname_words.hit_count` 是聚合值，删日志不影响 ——
"历史命中过多少次"（发现高频词/误杀大户）与"还剩多少原文证据"（申诉材料）是两个问题。

**测试**：后端 649 → **656 项**（新增 `tests/test_hit_logs.py` 7 项，含启动清理的集成验证）。
