#### P1-28 详情：资讯正文落地（E1）
**问题定性**：这是审查清单里唯一「产品可信度」级的问题——详情页的三段
「据相关方面介绍……」是前端常量，任何资讯点进去都一样；而服务端其实早就
拿到了正文（`content:encoded`），只是在 fetcher 里被丢弃（只提了图）。

**数据流（五站，每站一个明确的取舍）**

| 站 | 做法 | 取舍 |
| --- | --- | --- |
| 抓取 | `content:encoded`（RSS）/ `content`（Atom）优先，**回退 description** | 很多源只给摘要字段，但那也是真实文本，比「暂无正文」更有信息量 |
| 清洗 | `_clean_paragraphs`：块级标签与 `<br>` → 换行、去标签、解实体、段内压空白 | 与 `_clean`（整段压成一行，只适合摘要）**刻意分工**；段落是前端分段的依据 |
| 截断 | 按**段落边界**截到 8000 字符 | 宁可少一段，不在句子中间砍断；单段即超限才硬截断（防几千字无换行的源） |
| 入库 | 新增写 `content`；增量**非空才覆盖**；空正文落 `NULL` | 某轮抓到无正文的条目不该把已有正文抹掉；NULL 与空串可区分「源没给」 |
| 下发 | **只有详情接口返回 `content`**，`to_out` 不含 | 一页 20 条 × 几 KB 是纯浪费；无正文返回 `null`，前端显示「暂无正文」 |

**前端**：`NewsDetail.vue` 按 `\n` 切段渲染 `<p class="detail__para">`，
无段落时渲染 `.detail__para--empty`「暂无正文」。**不再有任何写死的正文**
（`views/NewsDetail.spec.ts` 4 项含「不渲染据相关方面介绍」回归断言）。

**测试**：`test_units.py` +9（正文提取/清洗/截断/回退/空源）、
`test_api.py` +3（列表不含 content / 详情返回真实正文 / 无正文为 null）、
`test_migrations.py` +1（0025 列可空且无索引）、`test_sources.py` +4
（`TestUpsertContent`：落库/增量刷新/空不抹掉/落 NULL）、
`NewsDetail.spec.ts` 4 项、契约 +2（列表不带正文、详情 content 类型）。
