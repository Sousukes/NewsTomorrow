#### P1-16 详情：抓取链路治理（并发化 / 礼貌抓取 / 超时告警）
**执行模型**（`app/feeds/ingest.py::collect`）

| 阶段 | 行为 | 为什么 |
| --- | --- | --- |
| 分组 | 按 `url` 的 host 分组，**保持权重降序的相对顺序** | 同站点源一次只发一个请求；并发的意义是省等待，不是打同一站点 N 遍 |
| 抓取 | 组间线程池并发（`FEED_MAX_CONCURRENCY`），组内串行 + 间隙 `FEED_HOST_GAP_SECONDS` | 源变多后不再线性变慢 |
| 合并 | 按 `srcs`（权重降序）**串行** `setdefault` | 「同 id 保留先到」是先到先得；并发合并会让"高权重先入库"随机化 |
| 回写 | `stats` 按权重序（非完成序）；`skipped=True` 的源**不刷新**健康状态 | 顺序不随网络快慢漂移；按礼仪跳过 ≠ 抓失败 |

**礼貌控制**

| 机制 | 配置 | 说明 |
| --- | --- | --- |
| 遵守 robots.txt | `rss_sources.respect_robots`（默认 `true`，逐源可关） | 取不到（404/不可达）→ **放行**；被禁 → 记 `last_status=error` + 原因（不静默抓取）；按 host 缓存 TTL `FEED_ROBOTS_TTL_HOURS` |
| 同站间隙 | `FEED_HOST_GAP_SECONDS`（1.5s） | 同 host 多个源串行时的喘息 |
| 单源最小间隔 | `FEED_MIN_INTERVAL_MINUTES`（10） | 定时任务与手动触发叠加时不重复打同一个源 |
| Crawl-delay | robots 声明 | 尊重，但**封顶 5s**（对方写极大值不能把整轮拖死） |

**健康告警**（`app/feeds/alert.py`，每轮抓取收尾执行）

| 项 | 规则 |
| --- | --- |
| 判定 | `last_status='error'`，或 `last_fetched_at` 为空 / 早于 `FEED_ALERT_STALE_HOURS`；**只看启用中的源** |
| 收件人 | 管理能力（`ADMIN_PHONES` ∪ `admin_users`）→ **已注册**用户，投递 `type='system'` 消息 |
| 节流 | 同源最小间隔 `FEED_ALERT_MIN_INTERVAL_HOURS`，锚点 `rss_sources.last_alerted_at`（**落库**，多实例共享） |
| 边界 | 无收件人 → **不推进锚点**（没通知到人就不占窗口）；告警异常被调用方吞掉，不影响抓取 |
| 开关 | `FEED_ALERT_ENABLED`（默认 true） |
