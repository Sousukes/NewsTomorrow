#### P1-36 详情：运维接口访问控制（C5）
**问题**：`/api/health`、`/api/metrics` 完全公开，前者下发连接池状态与热度重算状态，
后者下发 Top20 路径分布——内部可观测面被外部可读。

**规则**

| 配置 | 行为 |
| --- | --- |
| 设置 `OPS_TOKEN` | 必须携带 `Authorization: Bearer <token>` **或** `X-Ops-Token: <token>`；否则 **403 / 40303** |
| 未设置 + `development` | 放行（本地 / CI / 契约检查零改动） |
| 未设置 + `production` | 拒绝 **403 / 40303**（fail-closed）+ 启动告警 |

**设计取舍**

- **403 而非 401**：401 在本项目 = 会话失效（前端清登录态并跳登录页），运维接口与用户会话无关。
- 用户 JWT **不能**当运维令牌（不同信任域）。
- `secrets.compare_digest` 定时安全比较。
- 依赖在**调用时**读 `config.OPS_TOKEN` / `config.IS_PRODUCTION`（模块属性），
  否则测试无法 monkeypatch——与 `admin.is_admin` 读 `ADMIN_PHONES` 同一理由。

**生产探活**

```bash
curl -H "X-Ops-Token: $OPS_TOKEN" http://127.0.0.1:8000/api/health
```

> 生产未配置 `OPS_TOKEN` 时 `/api/health` 也 403：健康检查带池状态，与指标同属内部可观测面。
> 探针不便带令牌时，应由内网独占该路径或另设不含内部状态的存活探针。

**测试**：后端 635 → **649 项**（新增 `tests/test_ops_auth.py` 14 项）。
