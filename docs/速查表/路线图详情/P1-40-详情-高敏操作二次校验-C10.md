#### P1-40 详情：高敏操作二次校验（C10）
**接口**

| 接口 | 说明 |
| --- | --- |
| `POST /api/auth/step-up` | 入参 `{ password }`（**不收手机号**，身份取 access 令牌）；返回 `{ stepUpToken, expiresIn }`（默认 300 秒） |
| 受护端点 | 请求头 `X-Step-Up-Token`；缺失/无效/类型不符/已吊销 → **403 + 40304** |

**覆盖的 5 个端点**（判据：不可逆或影响全局）

| 端点 | 理由 |
| --- | --- |
| `PUT /me/nickname` | 用户侧唯一改身份的操作，且影响人工复核状态 |
| `POST /api/admin/users` | 授权管理员：一次误操作 = 把管理后台交出去 |
| `DELETE /api/admin/users/{phone}` | 回收管理员：影响面在「人」不在数据 |
| `DELETE /api/admin/sources/{key}` | 影响全站抓取，恢复要靠审计快照手工重建 |
| `POST /api/admin/sources/reset` | 丢弃全部自定义源，恢复出厂 |

**未覆盖**：内容治理类（hide/restore/review、词库增删）——可逆 + 有审计日志，
检测能力已具备；机制就绪后纳入只需加一个 `Depends(require_step_up)`。

**与既有机制的关系**：账号维度锁定复用 `login_guard`（scope=`stepup`，
失败 5 次即锁，与登录互不影响）；令牌复用 JWT 类型校验（`typ=stepup`，
与 access/refresh 三者互不通用）与 `token_version` 吊销（登出即失效）。

**前端流程**：`40304` → `http.ts` 广播 `STEP_UP_REQUIRED_EVENT` 并挂起 →
`StepUpDialog.vue`（挂 App 根部）收密码 → `POST /auth/step-up` → 令牌进内存
（5 分钟，刷新即失效）→ 原请求带 `X-Step-Up-Token` 重试一次。取消/失败按原
错误抛出；一次请求最多弹一次。
