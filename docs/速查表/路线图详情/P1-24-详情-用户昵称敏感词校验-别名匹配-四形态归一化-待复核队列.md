#### P1-24 详情：用户昵称敏感词校验（别名匹配 / 四形态归一化 / 待复核队列）
**补的缺口**：P1-23 给评论加了事前闸门，但昵称——评论之外第二个用户可控的展示面——
此前的唯一写入点是**注册时的一句话**（`body.name or 默认名`）：没有任何修改入口、
也没有任何校验。一个脏昵称会跟着用户的每一条评论、每一个通知展示出去，
等于让绕过者换个地方贴。本批补上 `PUT /me/nickname`（注册与改名同一条链）+ 昵称词库
+ 待复核队列。

| 设计 | 规则 |
| --- | --- |
| 注册与改名同链 | 两个写入口共用同一个引擎入口，**规则不搞两套**。刻意**不做追溯式回填**——词库事后变严时，老名字在**下一次保存时**同样被校验，复核队列针对「新提交」，不回头翻旧账 |
| 三动作，**无 mask** | `block` = 拒绝设置、**不保存**（**40006**，提示**不回显命中词**——回显等于给绕过者一份「哪些词不能起」的对照表）；`review` = **放行** + 置 `name_pending_review` 进人工队列（**默认**）；`allow` = 白名单**完全包裹**才豁免；`pass` = 原样保存并**清除**待复核标志（它只描述**当前名字**的审核状态，当初提交过什么由命中日志留痕） |
| 为什么没有 mask | 昵称是账号级属性，「脱敏后照常发布」意味着**改掉用户自己起的名字**，而他此刻改不了。默认 review 而非 block：机器的判断是概率性的，「先放行再让人看」比吞掉用户的名字代价小 |
| 默认 review 而非 block | 同上；block 不可逆且用户此刻无法在输入框里改一个不让他保存的名字 |
| 归一化七类绕过 | 逐字符 NFKC → `casefold()` → 只保留 Unicode `L*`/`N*`（空格/标点/零宽/emoji 全丢）；**重复压缩**（`collapsed` 形态，`aabbcc→abc`——昵称短、无语义，压缩误杀面小，故评论刻意不做的这里做）；**leetspeak**（`4/@→a、3→e、1/!/|/l→i、0→o、5/$→s、7/+→t、8→b、6/9→g、2→z`——模式串与文本走**同一条管道**，一对一归并任意组合都安全）；**数字插字**（`nodigits` 形态，「博0彩→博彩」，与 leetspeak 互补：0 当字母 o 用还是当噪声删，两种形态都扫）；**繁简 curated 表**（内置常用繁→简子集，**零运行时依赖**，未覆盖的繁体变体由运营配别名） |
| 拼音谐音走别名 | 同音字替换（傻→莎）没有字符级算法可解（需要字→拼音表），由运营发现后补 `aliases`（拼音全拼/首字母/谐音/变形），**与主词走同一条归一化管道**——这是零新依赖下覆盖「shabi」「sb」类字母绕过的路线 |
| 四形态 | `base / nodigits / collapsed / collapsed-nodigits`，各带 `index_map`（命中回到原文定位写日志）；`collapsed` 两形态受 `NICKNAME_COLLAPSE_REPEATS` 控制，关闭时对应自动机为空 |
| 形状校验先行 | 长度 2~24（**码点**计，emoji 记 1）；字符白名单 `L*`/`N*` + `_ - · . ・` + 内部空格；代理字符（lone surrogate）与控制字符（Cc）拒绝。**顺序刻意「字符集先于长度」**——字符根本不能用比太长更根本。全部失败统一 **42203**，消息即面向用户的提示 |
| 引擎复用不重造 | **复用** `moderation.AhoCorasick` 自动机与指纹缓存模式（不复制第二份实现）；**新表不复用** `sensitive_words`——不同语义的资源不挤进同一张表，否则「这个词是拦评论还是拦昵称」永远说不清 |
| 热更新 | 指纹 `COUNT(*) + MAX(updated_at)` + TTL 30s；管理端改词（**含改别名**——别名是模式串的一部分，改了不重载等于没改）→ `invalidate()` 本进程保存即生效；集群其他实例靠 TTL 兜底 + `POST /admin/nickname-words/reload` 手动触发 |
| 误杀控制 | 默认 review / allow 包裹豁免 / **最短词长 2 挡在入库且主词与每个别名逐个查**（引擎加载会静默跳过过短形态，「配了却没生效」比报错难发现得多）/ block 不回显命中词 / 命中日志留 `snippet`（昵称整体即上下文，判断误杀不需要更多信息）/ **停用优于删除** / **未知 action 兜底 review**（数据异常时降级「放行 + 让人看一眼」，不吞用户昵称） |

**结构契约（迁移 0024）**

| 表 / 列 | 说明 |
| --- | --- |
| `nickname_words` | `word` **唯一索引** / `action`(block\|review\|allow) / `category` / **`aliases`**（JSON 数组，PG 上 JSONB——拼音/谐音/变形）/ `enabled` / `hit_count` / `created_by` / `created_at` / `updated_at`（参与指纹，有索引） |
| `nickname_hits` | 一次提交一行，记**词本身**（删词后日志仍可读）+ **`matched`**（实际命中的模式：主词或某条别名——回答「哪条别名拦住的」，也是判断「该补哪个别名」的依据）/ `action` / `source`(`register`\|`update`) / `user_id` / `user_name` / `snippet`（当次提交的昵称原文）/ `created_at`。**block 也留痕**——「拦了多少次改名」不能是黑箱，也识别不出反复尝试绕过 |
| `users` +2 列 | `name_pending_review`（非空默认 false，**不建索引**——待复核集预期很小，加了只会拖慢每次昵称写入）/ `name_reviewed_at`（复核时间，复核动作同样要留痕） |

**接口**（`PUT /me/nickname` 需登录；其余需登录 + 具备管理能力）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PUT | `/api/me/nickname` | 改昵称：形状**42203** / block **40006**（旧名**不被改写**）/ review 放行 + 置位 / pass 清标志；返回 `{name, result, reason, pendingReview}`。未登录 401 |
| GET | `/api/admin/nickname-words` | `keyword`（≤50，**只匹配主词**——别名在每行 `aliases` 可见，为搜别名把 JSON 列拖进 ILIKE 不值得）/ `action`（空\|block\|review\|allow）/ `enabled`（三态）/ `limit`(1~500)+`offset`；排序 `hitCount DESC, id DESC` |
| POST | `/api/admin/nickname-words` | `{word, action, category, aliases, enabled}`；主词或**任一别名**归一化后不足 2 个有效字符 → **42204**（文案「…至少需 2 个有效字符（空格与标点不计）」）；重复 → **40906**；保存即 `invalidate()` |
| PATCH | `/api/admin/nickname-words/:id` | 局部更新（动作/分组/别名/启用），**不允许改词本身**（改词等于删一条加一条）；`aliases` 传空数组 = 清空、不传 = 不动（schema 用 `None` 区分）；字段级 diff 审计，无变化不记 |
| DELETE | `/api/admin/nickname-words/:id` | 审计留快照；不存在 **40407**。通常**停用优于删除** |
| POST | `/api/admin/nickname-words/reload` | 强制重建**本进程**索引，返回生效条数 `{count}` |
| GET | `/api/admin/nickname-hits` | 命中日志（**只读、不清理**）：`word` / `action`(block\|review) / `source`(register\|update) / `userId`（**驼峰**）/ `limit`(1~100) + `cursor`(id keyset)；返回 `{list, total, hasMore, nextCursor}` |
| GET | `/api/admin/nickname-reviews` | 待复核队列：`keyword` 按**当前**昵称/手机号 ILIKE；`limit`(1~100)+`offset`；行含 `userId/name/phone/flaggedAt/flaggedName/flaggedMatched`（三个标量子查询取该用户**最近一条 review 级命中**——队列回答「哪个提交需要人看」，不是「他现在叫什么」）；按最近被标记降序 |
| POST | `/api/admin/nickname-reviews/:userId` | 通过人工复核（**幂等**）：只清 `name_pending_review` + 写 `name_reviewed_at`，**不改昵称本身**（名字是用户自己起的，复核是「人看过了」这个事实，不是运营替他改名；仍不适应走线下处理——本站不提供改他人昵称的能力）；用户不存在 **40408** |
