#### P1-34 详情：前端列表状态分桶 + 竞态守卫（A4）
**问题**：`stores/news.ts` 只有一个 `list` + `currentChannel`，首页与视频页共用 →
视频页 `fetchNews('video')` 覆盖首页列表（KeepAlive 下切回首页看到视频内容，
触底 `loadMore()` 还按 `video` 频道往首页追加）；`loadMore` 在途时切频道，
旧响应会把旧频道条目追加进新列表并覆盖 `cursor`。

**API 变更（前端内部，无 HTTP 契约变更）**

| 旧 | 新 |
| --- | --- |
| `news.list` / `news.hasMore` / `news.loading` / `news.error` / `news.loadingMore` / `news.page` / `news.total` / `news.cursor` / `news.currentChannel` / `news.currentSort` | **已移除**（全局单例状态是根因） |
| `news.fetchNews(channel?, sort?)` | `news.fetchNews(channel, sort)`（**必传**） |
| `news.loadMore()` | `news.loadMore(channel, sort)`（**必传**） |
| `news.resetPaging()` | `news.resetPaging(channel, sort)`（**必传**） |
| — | `news.bucketOf(channel, sort)` → `NewsBucket`（`list/loading/error/page/total/hasMore/loadingMore/cursor/generation`） |
| — | `news.listOf(channel, sort)` → `NewsItem[]` |

**桶 = (频道 × 排序)**：7 频道 × 3 排序 = 21 个桶，store 初始化时**预建**（不在渲染期创建）。
排序也进桶键，因为排序变了服务端游标即失效。

**代次守卫**：`generation` 每次 `fetchNews` / `resetPaging` 递增；`loadMore` 捕获调用时
的代次，响应回来若代次已变则整体丢弃（不追加、不覆盖游标、不改 `hasMore`、不误清
`loadingMore`）。同一桶内「先发的 fetch 后返回」同样丢弃。

**视图**：`HomeFeed` 用 `bucketOf(activeChannel, activeSort)`；`Videos` 固定 `video` 桶
（并补上无限滚动 + 骨架 + 错误/末页提示）。`getById` 遍历全部桶 + 详情缓存 + mock。

**测试**：前端 484 → **488 项**（新增分桶隔离 3 项 + 竞态守卫 4 项）。
