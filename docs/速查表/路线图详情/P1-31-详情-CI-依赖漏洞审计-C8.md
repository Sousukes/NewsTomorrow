#### P1-31 详情：CI 依赖漏洞审计（C8）
**为什么单独立项**：此前的 CI 只验「代码能跑」，不验「依赖有没有已知漏洞」——
一个 high 级 CVE 可以在全绿的状态下潜伏到被利用。C8 补上这道闸门。

| Job | 步骤 | 位置 |
| --- | --- | --- |
| frontend | `npm audit --audit-level=high` | `npm ci` 之后、类型检查之前（fail fast） |
| backend | `pip-audit`（先 `pip install --upgrade pip`） | `pip install -r requirements.txt` 之后 |

**两个「不这么做就会天天红」的细节**

1. **pip-audit 审计整个已安装环境**：venv 自带的 pip 也在范围内。旧版 pip
   自身就有通告（PYSEC-2026-3721，26.2 修复）——不先升级 pip，CI 会红在
   一个与项目无关的包上。审计类闸门最怕这种「狼来了」：红几次之后，
   团队对红色的信任就没了，真漏洞也被一起忽略。
2. **npm audit 走官方 registry 的审计端点**：本机开发常用 npmmirror，
   而镜像不实现 `/-/npm/v1/security/*`（报 `NOT_IMPLEMENTED`）。这不是
   配置错误，是镜像能力缺口——本地自查时临时
   `--registry=https://registry.npmjs.org`，CI 用默认 registry 无此事。

**阈值为什么取 high**：低危/中危通告的修复主动权常在间接依赖上游，
拦在 CI 里只会制造无力修复的红色。高危及以上才具备「不修不能上线」的
性质；其余交给 dependabot 与人工评估。

**本地复验（CI 改动的唯一可信验证方式）**：按 CI 同款命令链在干净 venv
（只装 requirements.txt）复跑——Python 零发现、npm 0 漏洞；当前依赖面
干净，闸门上线不会立刻红。
