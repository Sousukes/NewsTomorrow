#### P1-41 详情：修改密码 + 管理员代重置 + 强制改密（C4）
**接口**

| 接口 | 入参 | 前置 | 返回 |
| --- | --- | --- | --- |
| `PUT /api/auth/password` | `{ oldPassword, newPassword }` | 登录 + 二次校验 | **新的一对**令牌（旧的已作废） |

**错误码**：`40101` 原密码不正确 / `42205` 新旧密码相同 / `40007` 不能重置自己 /
`40400` 用户不存在（与公开接口同码，不泄露手机号是否注册）/ `40305` 受限态拦写。

**受限态（`users.must_change_password`，迁移 0028）**

| 允许 | 拦截（40305） |
| --- | --- |
| 浏览/搜索/看消息/改资料/**改密码** | 发评论·点赞·删评论、收藏与历史写入、改昵称、**任何管理端** |

拦截点只有两个：用户侧写操作用 `deps.require_password_current` 依赖；
管理端全部端点收敛在 `admin.require_admin` 一处——新增端点自动继承，不会漏。

**前端**：`/change-password` 一个页面承接「主动改密」与「被强制改密」；

他们不在管理员白名单里），临时密码带复制按钮、只显示一次。

| **P1-41（C4）** | **修改密码 + 管理员代重置 + 强制改密** | 此前**没有任何改密通道**：用户忘记密码只能无解，管理员也只能新建账号（旧号数据与身份就此悬空）。本项目**没有可送达的凭证通道**（无短信/邮箱，即 backlog C3），故落地「管理员线下核实 + 代发一次性临时密码 + 强制本人改密」——把「验证身份」放在人身上，而不是假装系统能确认你是谁。① `PUT /api/auth/password` 走**两道证明**（C10 二次校验 + `oldPassword`）；改密后自增 `token_version` 作废全部旧凭证，同时**下发新的一对**（否则用户改完被自己踢下线）。② `POST /api/admin/users/:phone/reset-password`：临时密码**服务端生成**（剔除 `0/O`、`1/l/I` 等易混字符——靠口头/手写传达）；**不能重置自己**（40007）；用户不存在返回 **40400**（与公开接口同码，不泄露手机号是否注册）；**审计不含明文**（审计表长期留存，写明文等于给只读权限者发密码清单，有断言守住）。③ 迁移 **0028** 加 `must_change_password`（NOT NULL + server_default false，不建索引）。④ 受限态拦截只写**两处**：用户侧写操作用 `deps.require_password_current`，管理端**全部**端点收敛在 `require_admin`（新增端点自动继承）——拿临时密码管后台 = 临时密码长期有效，「强制改密」名存实亡；**只拦写不拦读**（锁死账号除了让人焦急没有安全收益）。前端：`/change-password` 一个页面承接主动/被动两条入口，标志随登录下发并落盘，`router.beforeEach` 只放行改密页与登录页；管理端做**手机号输入**式重置（正主是普通用户，他们不在管理员白名单里）。**顺带补齐 mock 缺口**：mock 原无注册端点，契约无法在双端跑改密链路，补 `POST /auth/register` 且登录/二次校验改比对账号当前密码。后端 699 → **721**，前端 512 → **519**，契约双端默认 56 → **64**、CHECK_ADMIN 262 → **277**
| **P1-42（B2 + B3）** | **资讯列表热路径的两处性能债** | **B2**：`GET /api/news` 的 `page` 改**可选**——不传即走 keyset 分页（首页与续页同一套查询），**不再全表 `count()`**；此前首页（还没拿到 cursor 时）落在 offset 分支，等于**每次打开页面都做一次全表 count**，主路径 100% 命中。保留 offset 分支是刻意的（仍需要「第 N 页 / 共多少条」语义的调用方，直接删会让老客户端崩）。前端 `api/news.ts` 改为一律不发 `page` 并有断言守住；`total` 变 `null` 时回落 `list.length`——用户侧界面本来就不消费列表 `total`（只有管理端与搜索页在用），无可见影响。**测试断言的是「不出现 COUNT 语句」而非响应形状**：只把 `total` 改 `null` 而底下照样 `count()`，契约看不出差别、债原封不动。**B3**：`for-you` 的频道偏好原本每请求两次 JOIN + GROUP BY，一次翻页十几个请求就是同一秒算十几次相同聚合 → 新增 `app/cache.py`（进程内 / Redis 双实现，与 `ratelimit` 同口径：探活失败降级+只告警一次、**缓存异常一律不许冒泡**、键前缀 `cache:` 与限流 `rl:` 分开），TTL 5 分钟；**失效优先于过期**（收藏/浏览/合并/清空任一写入路径都删键，键拼法只在一处——散开写迟早拼错，而拼错的后果是缓存永不失效且**无任何报错**）；**空偏好不缓存**（多数访客属于这类，只堆永不命中的键）。`CACHE_ENABLED` 必须存在的原因：每个测试文件重建 sqlite 且 `user_id` 从 1 重新分配，进程内缓存会让上一个文件的「用户 1」被下一个文件的另一个「用户 1」命中，症状是 for-you 排序断言**只在全量跑时**随机失败。mock 同步（此前 `/news` 压根没实现游标）。后端 721 → **735**，前端 519 → **523**，契约双端默认 64 → **68**、CHECK_ADMIN 277 → **281** |
| **P1-43（B4）** | **图片代理 + CSP 收紧** | 配图此前由浏览器**直连源站**，代价有三：① 源站一挂就裂图（图在源站，我们只存 URL）；② CSP 的 `img-src` 必须放行 `https:`，而 **CSP 恰恰挡不住 `<img src=https://evil/x>` 这类外泄型载荷**（几十个无关源站都能看到用户 IP 与浏览行为）；③ 没有尺寸协商。新增 `GET /api/img?url=…&w=…`。它是**教科书式 SSRF 攻击面**（把"能发请求的服务器"交给用户指定目标），所以 `app/routers/img.py` 里**防线比功能多**：协议白名单；**逐条**检查 DNS 结果非公网即拒（多 A 记录混入内网、`169.254.169.254` 云元数据）；**跳转逐跳复检**（≤3 跳手动跟随——外站 302 到内网是最常见绕过）；5MB 上限+超时；只放行图片 `Content-Type` 且**不含 SVG**（同源代理转发 HTML/JS 就是存储型 XSS 入口）+ `nosniff`/`Content-Disposition`；缓存键=(URL,宽度)且**宽度走白名单**（任意 `w` 就是撑爆缓存的入口）。**已知边界（写进代码不藏）**：DNS 解析与建连间有 TOCTOU 窗口，彻底消除要自定义 transport 钉住已校验 IP，当前不接受这个复杂度。缩略图/WebP 装了 Pillow 才生效（`try: import PIL`）且**不放大**，它是 native 依赖故**不进 requirements.txt**，另立 `requirements-optional.txt` 由部署方决定。前端 `proxiedImageUrl()` 三条分支：相对路径原样、mock 模式原样、真实后端走代理。**CSP 随之收紧**：有后端时 `img-src` 收掉 `https:`（**这挡掉的正是纯 CSP 挡不住的外泄型载荷**）。两条诚实边界：`media-src` 仍放行 `https:`（**视频未代理**，已开 B7 单独跟踪）、mock 演示态无后端代理故保留。测试主体是 SSRF 拒绝矩阵，含**"被拒目标一次 HTTP 请求都不该发出"**。契约只断言**安全策略**（取图要出网，契约环境无外网）。后端 735 → **764**，前端 523 → **532**，契约双端默认 68 → **72**、CHECK_ADMIN 277 → **285** |
| **P1-44（D8）** | **容器化 + 迁移前置钩子** | 形态 = postgres + redis + `migrate`（一次性）+ backend + nginx(SPA + `/api` 反代)，**前后端同源**（nginx 反代、前端不带 `VITE_API_BASE`）→ 无 CORS 预检、CSP 收得最紧、不必把后端地址硬编进构建产物。核心是**迁移前置钩子**：本项目只有一个 schema 事实源（Alembic），没跑迁移就起服务的症状是「列不存在」——报错指向业务查询、真正原因是环境没升级，这类债 CI 里看不见（CI 自己会先 upgrade）、只在部署时炸。`scripts/entrypoint.sh` 用 `set -e` + `python -m alembic upgrade head` + `exec uvicorn`：**迁移失败即停**（起了也只会满屏 500，还会把"环境没升级"伪装成"代码有 bug"），`exec` 让 uvicorn 接管 PID 1 才能收 SIGTERM。compose 里 `migrate` 是一次性服务、backend 设 `RUN_MIGRATIONS=false` 并 `depends_on: service_completed_successfully`——**多副本并发跑迁移会互相锁死同一份 DDL**，此形态也为 B5（抓取 worker 独立进程）留好位置。**三个自己踩出来的坑**：① `ENVIRONMENT=production` 下 `/api/health` 需 `OPS_TOKEN`（C5 fail-closed），healthcheck 不带令牌 → 容器永远 unhealthy → frontend 因 `service_healthy` 永不启动；改成带 `X-Ops-Token`，**这是刻意**——忘配密钥的后果是"起不来"而非悄悄裸奔。② `VITE_USE_MOCK` **必须显式传 `false`**（默认值是"没配 API_BASE 就当演示态"，而我们刻意留空 → 否则生产镜像静默跑内置 mock，界面完全看不出来）。③ entrypoint 调 `python -m alembic` 而非 `alembic`（与 CI 同形态），测试按控制台脚本打桩会让**真 alembic 跑起来**，本机恰好因 python 没装 alembic 快速失败、把问题**掩盖成"行为正确"**。nginx：`/api/` **不做** SPA fallback（否则接口 404 返回 HTML，前端 `json()` 报完全误导的解析错误）；`index.html` 不可缓存；CSP 只下发 `frame-ancestors 'none'`（meta 表达不了的那一条）——**两份策略各写一遍必然漂移**，而 CSP 多头取交集。**诚实边界：本机无 Docker 守护进程，镜像未在 CI 验证**；保证的是 entrypoint 三条路径**实际执行**验证（POSIX）+ 15 项部署文件静态断言，已开 backlog「CI 验证镜像可构建」。文档 `docs/deploy.md`。后端 764 → **782** |
