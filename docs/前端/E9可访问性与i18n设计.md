# E9 可访问性（a11y）与 i18n · 设计方案（待确认）

> 状态：**方案已成型，6 个决策点待确认**（沿用 E6b / E2 / E3 / E7 / E8 流程：不确认不动手）。
> 来源：backlog E9「a11y 与 i18n」。本轮只做现状扫描与方案，未改任何代码。

## 一、现状核实（全部为实测数据，非印象）

**先说结论：这个项目在 a11y 上不是"零基础"，而是"骨架有、关节缺"。**
已有 115 处 `aria-*`、16 处键盘处理、全局 `:focus-visible` 与 `prefers-reduced-motion`、
`<nav>/<main>/<header>` 地标、ReportDialog 的 Escape 与 radiogroup——这些说明作者有意识。
缺的是**最关键的那几处**。

### 1.1 致命：核心交互纯鼠标

| 位置 | 现状 | 影响 |
| --- | --- | --- |
| `components/NewsCard.vue:61` | `<article @click="emit('click', item.id)">` —— 无 `tabindex`、无 `role`、无 `@keydown` | **全应用最核心的交互（打开一条资讯）键盘完全不可达**。信息流里的每一条都是死路 |
| `components/BannerCarousel.vue:125` | `<div class="banner__slide" @click>` 同上 | 轮播位不可达 |

全仓 `tabindex` 只有 **1 处**——而仅 NewsCard 一项就影响 100% 的内容浏览路径。

### 1.2 弹窗：三个组件三种成熟度

| 组件 | role/aria-modal | Escape | 初始焦点 | 焦点陷阱 | 焦点还原 |
| --- | --- | --- | --- | --- | --- |
| `ReportDialog` | ✅ | ✅ | ✅ | ❌ | ❌ |
| `LoginGateDialog` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `StepUpDialog` | ✅ | ❌ | ❌ | ❌ | ❌ |

**没有焦点陷阱的 `aria-modal="true"` 是半个谎言**：屏幕阅读器被告知"外界不可交互"，
而 Tab 键仍能跑到背后的页面上。焦点还原同理——关掉弹窗后焦点回到 `<body>`，
键盘用户要从头 Tab 一遍。

### 1.3 对比度：实测不达标（这是本项最硬的证据）

用 WCAG 2.1 相对亮度公式实测 `tokens.css` 的色对：

| 色对 | 实测 | AA 要求 | 结论 |
| --- | --- | --- | --- |
| `--color-text-secondary #9a9fa8` on 白卡 `#ffffff` | **2.66:1** | 4.5:1（正文） | ✗ |
| 同上 on 页底 `#f4f5f6` | **2.44:1** | 4.5:1 | ✗ |
| `--color-text-primary #222222` on 白卡 | 15.91:1 | 4.5:1 | ✓ |
| `--color-primary #2d6cff` on 白卡 | 4.47:1 | 4.5:1（正文）/ 3:1（大字、图形） | 大字/图形 ✓，**正文擦边不足** |
| 白字 on `--color-primary` | 4.47:1 | 同上 | 同上 |
| `--color-error #e5484d` on `#fceded` | 3.44:1 | 4.5:1 | 大字/图形 ✓，正文 ✗ |
| `--color-border #e5e6e8` on 白卡 | 1.25:1 | 3:1（有意义的控件边界） | ✗（装饰性边框可豁免） |
| 暗色主题 secondary `#8f959e` on `#1c1e22` | 5.53:1 | 4.5:1 | ✓ |

**`--color-text-secondary` 是全站元信息（来源 / 时间 / 评论数 / 次要说明）的颜色**，
出现频率仅次于正文。它的 2.66:1 意味着：在正常视力下尚可辨认，但在弱光、
低质量屏幕、老年用户、色觉异常用户面前基本是"看得见但读不清"。

实测达标的候选值（需同时在白卡与页底上 ≥4.5:1）：

| 候选 | on 白卡 | on 页底 | 结论 |
| --- | --- | --- | --- |
| `#6b7280` | 4.83 | 4.43 | 页底差 0.07 |
| **`#666c76`** | **5.29** | **4.84** | ✓ 两处都过 |

### 1.4 其余缺口（小但真实）

- **4 个 `<img>` 无 `alt`**（`NewsCard` ×3、`BannerCarousel` ×1）：图片加载失败或读屏时
  没有任何替代文本；
- **`TabBar` / `ChannelTabs` 当前项只有 `is-active` 类**，无 `aria-current`：
  读屏用户无法知道"我在哪个 tab"；
- **无跳过导航链接（skip link）**：每页开头是 AppNav + ChannelTabs + TabBar，
  键盘用户每次进页面要 Tab 穿过十几个控件才能到内容；
- **`App.vue` 的 `<h1>` 是陈列区标题**（"明日头条 · Vue 3 多页应用"），
  而各视图内部也有 `<h1>`——同一文档出现多个 h1，标题层级不成树。

### 1.5 i18n：全量硬编码中文

`grep` 未发现任何 i18n 库或词条表；文案直接写在模板与常量里（含 mock 数据、错误提示、
无障碍标签）。`index.html` 的 `lang="zh-CN"` 与 manifest 的 `lang` 正确。

**这不是缺陷，是范围选择**：产品当前只有中文一种语言，没有任何多语言需求。
为一个不存在的需求引入 `vue-i18n`，代价是每个字符串都要过一层 key、每次改文案
都要动两个文件，而收益为零。**本方案建议明确"不做 i18n"，并写清触发条件**（见 D6），
而不是含糊地挂在 backlog 上。

## 二、方案范围

1. **核心交互键盘可达**：资讯卡片、轮播位（D2）；
2. **弹窗行为完整**：Escape + 焦点陷阱 + 焦点还原，抽成一处（D3）；
3. **对比度达标**：色板按角色拆分，并用**测试**守住（D4）；
4. **导航语义**：skip link、`aria-current`、图片 `alt`（D5）；
5. **i18n**：显式不做，记录触发条件（D6）。

## 三、6 个决策点（待确认）

### D1 范围：只做 a11y，还是 a11y + i18n 一起？

**推荐只做 a11y**。i18n 在本项目属于"没有需求的功能"，做它等于给未来的自己增加
维护面（见 1.5）。两者混在一批里会让"a11y 是否达标"这个可验证目标被稀释。

### D2 资讯卡片的语义化：三种做法

| 方案 | 做法 | 代价 / 风险 |
| --- | --- | --- |
| A. `article` + `tabindex="0"` + `role="link"` + Enter 处理 | 改动最小 | 需自己处理 Enter/Space，且 `role="link"` 在 `article` 上语义怪；读屏会念"链接"但双击行为靠模拟 |
| B. 卡片内部放一个**覆盖整卡的 `<a href>`**（推荐） | 语义天然正确，浏览器自带 Enter、右键"新标签打开"、状态栏 URL 预览 | 卡片内的按钮（收藏/不感兴趣）需要 `position: relative; z-index` 抬起来，否则点击被链接吃掉 |
| C. 整卡换成 `<button>` | 语义正确 | 会丢掉"新标签打开"这类链接能力，且 button 里不能嵌 button（卡片内有收藏按钮，非法嵌套） |

**推荐 B**，理由：这是"链接"而不是"按钮"——它会导航到另一个 URL，用户的预期
包括中键点击、右键新标签打开、复制链接。**C 方案会直接产生非法 HTML**（嵌套按钮），
不是风格问题。

### D3 弹窗：抽 `useDialog` 还是逐个补？

**推荐抽 `src/composables/useDialog.ts`**，三件事一次做对：

1. **Escape 关闭**（三个组件统一）；
2. **焦点陷阱**：Tab / Shift+Tab 在弹窗内循环（`aria-modal="true"` 的诚实前提）；
3. **焦点还原**：关闭后焦点回到打开它的元素（`document.activeElement` 在打开时记下）。

逐个补的代价不是"写三遍"，而是**三份实现迟早分叉**——ReportDialog 已经有 Escape，
另两个没有，这就是分叉已经发生的证据。

### D4 对比度：怎么改才不破坏视觉层级

**推荐按"角色"拆 token，而不是整体调深**：

| token | 现值 | 新值 | 用途 |
| --- | --- | --- | --- |
| `--color-text-secondary` | `#9a9fa8` | **`#666c76`** | 元信息（来源/时间/评论数）——**必须可读** |
| `--color-text-tertiary`（新） | — | `#9a9fa8` | 纯装饰性小字（如分隔符 `·`、禁用态提示） |
| `--color-border-strong`（新） | — | `#c6c9d0` → 实测 1.66:1 仍不足 | 见下 |

两点必须讲清楚：

- **不能只把 `#9a9fa8` 全局替换成 `#666c76`**：视觉层级会塌——元信息与正文的对比
  从 15.9:1 vs 2.66:1 变成 15.9:1 vs 5.29:1，仍可区分，但原本"极淡"的设计意图
  （如时间戳、`·` 分隔符）会变得刺眼。拆成两个 token 才能"该读的清、该淡的淡"。
- **`--color-border-strong` 我不建议强推 3:1**：要让 `#e5e6e8` 达到 3:1 需压到约
  `#949494`，作为卡片描边会非常重。WCAG 1.4.11 只要求**有意义的控件边界**
  （输入框、复选框、焦点环）达 3:1，装饰性分隔线豁免。因此只给**表单控件**
  换深描边，卡片描边保持现状——这一条我会在实现时按控件逐处确认，不做全局替换。

**并用测试守住**：新增 `utils/contrast.ts`（相对亮度 + 比值，纯函数）+
`tokens.contrast.spec.ts` 断言"关键色对 ≥ AA"。这样以后任何人调色板都会立刻红，
而不是等下一次人工审计。

### D5 导航语义：做到哪一层？

**推荐四项一起做**（成本都很低，且都是"缺了就等于没做"的项）：

1. **skip link**：`<a href="#main" class="skip-link">跳到主要内容</a>`，聚焦时才可见；
2. **`aria-current="page"`**：TabBar / ChannelTabs 的当前项；
3. **`alt`**：4 个 `<img>` 补 alt——封面图用标题（`alt=""` 更合适时用空 alt 明确"装饰性"，
   而不是留空属性让读屏念文件名）；
4. **标题层级**：陈列区的 `<h1>` 降级为 `<p>`/`<h2>`，让视图内的 `<h1>` 成为文档唯一 h1。

### D6 i18n：显式不做，但写清触发条件

**推荐不做**，并在 backlog 里把 E9 拆成"a11y（做）"与"i18n（不做，附触发条件）"。
触发条件（任一条满足即重新评估）：

- 出现第二种目标语言（含"繁体中文"这种看似相近但用词不同的情况）；
- 需要按语言切换内容源（RSS 源本身多语）；
- 需要把界面文案交给非开发者维护（运营改文案不改代码）。

同时保留两条**低成本但重要**的现状：`<html lang="zh-CN">` 与 manifest 的 `lang`
已经正确——这是 i18n 的地基，改起来最便宜的两处已经在了。

## 四、验收标准

- **键盘完整走通主流程**：Tab 进页面 → skip link → 频道 → 卡片（Enter 打开）→
  详情 → 收藏 → 返回，全程无需鼠标；焦点始终可见；
- 三个弹窗：Escape 可关、Tab 不逃逸、关闭后焦点回到触发元素；
- `tokens.contrast.spec.ts` 全绿（关键色对 ≥ AA）；
- 4 个 `<img>` 有 `alt`（含明确的 `alt=""`）；
- `TabBar` / `ChannelTabs` 有 `aria-current`；
- 文档只有一个 `<h1>`；
- 现有 912 项测试不回归；`npm run verify` 0 error。
